# 本地交叉编码器：真实相关性评分实验

2026-10-04 更新：桌面实体图召回已接入现有本地重排模型，同时用于 L1 最终选择和 L2 起点选择；下方 2026-10-01 数据为历史实验。

模型在召回计时前校验并预加载，各会话共享权重。每次最多复核 16 个候选、评分阶段最多 500ms，仍受总召回预算限制。未安装或加载失败时保留原余弦门槛；设置 `CONTINUUM_GRAPH_EVIDENCE_SELECTION=cosine` 可显式使用旧策略，`CONTINUUM_GRAPH_RERANKER_DIR` 可指定已安装模型路径。不会自动下载模型。

当前筛选保留 logit≥0 的相关候选，再排除落后最高分超过 4 的弱匹配。开放式/多答案问题允许保留同一回答字段中的其他值：必须具有相同作用域、精确谓词版本、非值角色绑定、语境、有效时间、极性、陈述方式、条件和限定信息，且每条候选仍须独立通过绝对门槛。没有明确 valueRole 或语境不同，不做这种扩展；不会把整个关系的所有邻居补入答案。针对明确提到已有字面值的聚焦问题，限制为该值对应的事实，正反极性都保留。这些是暂定相关性策略，不是真值或概率校准。

本机合成样例复测：原 29 条质量用例由 16 条严格证据匹配提升为 23 条，另 12 个新增问法由 3 条提升为 10 条；本次没有额外错误证据，仍有漏召回。新增问法沿用同一语料，不能视为独立通用 benchmark。模型权重未训练、L1/L2 权威事实与关系未改变，未提交代码。

### 第二轮：重排文本与多答案选择

L1 最终证据与 L2 起点使用相同的重排文本构造器。只在主体的精确实体版本、审核、作用域、权限和动态来源均合格时，将记忆句首的主体称谓对齐为问题中明确使用的已审核别名；例如已确认“用户”和“我”是同一实体，才把评分视图中的“用户的职业……”表示为“我的职业……”。不改写对象中的名字、不推造身份；否定问法以及条件/转述等陈述保留原称谓。缺少的关系原文、字面参数、条件和陈述方式可从已采纳结构补入评分文本。实际返回的事实正文、引用及时间信息保持原样。

同一机器、同一批离线模型、相同候选数量和预算的对照：

| 用例 | 修改前 | 仅改善文本 | 文本＋分组选择 |
| --- | --- | --- | --- |
| 原有严格证据匹配 | 23/29 | 25/29 | 25/29 |
| 另外 12 个改写问法 | 10/12 | 11/12 | 11/12 |
| 新增 6 个多答案/细分属性探针 | 3/6 | 3/6 | 3/6 |

前两组均没有额外错误证据或评分超时，改善来自文本表示：补回“我是靠什么工作谋生的”，以及两个饮料枚举问法中漏掉的另一条事实。不能把这批提升归功于分组扩展；这些用例的不同来源有不同精确语境，不能为提高分数合并语境。33 项临时边界检查覆盖同字段不同值、跨主体/语境/时间/极性隔离、来源不可读、输出预算等；原有图模块回归 426 项通过，3 项可选测试跳过，memory 与桌面类型检查通过。

额外探针仍有两条复合问题证据不全，以及一条细分属性误选：“我喜欢喝什么牌子的饮料”在记忆仅有饮料种类时仍返回相关饮料；修改前也有该问题，修改后返回的相关值更多。相关性评分仍不等于证据充分性，不能据此生成不存在的品牌。该问题需要后续问题分解与所问属性/可回答性判断，不能宣称口语和多答案问题已全部解决。所有样例均为同一合成语料上的开发验证，未独立校准、未调用聊天 API；本轮临时验证程序完成后删除，已有仓库测试保留。

### 第三轮：受控问题规范化与一次补充检索

桌面默认开启本地受控版本，`CONTINUUM_GRAPH_QUERY_EXPANSION=off` 可关闭以进行对照；库接口默认关闭。现有模型只有向量编码器和重排器，没有新增生成模型或调用聊天 API，因此不是自由语义改写。“啥/啥时候/哪儿/为啥”及有限礼貌前缀可以规范化，已知实体名、字面值和引号内容受保护；不删除否定、时间、情态、数量或所问属性，不猜测领域同义词。

原问题与至多一个规范化版本分别计算向量、合并候选去重；底层用 RRF 合并名次，保留真实余弦分数供准入检查。实体与 Claim 查询向量按完整问法分别缓存，不能用规范化问题的向量冒充原问题。礼貌前缀不再遮住经过审核的“我”别名，实体身份仍来自精确版本引用。时间、关系类型和方向继续由原问题规划。

首轮无合格结果，或候选池被截断且输出名额未满时，才考虑一次补充操作：有未探索候选就扩大实体入口及候选池；只有等价表达变化时复用已检查候选进行一次重新评分。桌面候选池通常由 16 扩到 32，扩展上限 64；实体入口通常由 4 扩到 8，上限 32，仍受节点预算限制。输出数量和总时间预算不增加；没有新路径、时间不足、评分器不可用则跳过。额外操作失败或改变首轮已选证据时保留首轮结果，并继续进行最终来源/版本检查。不会通过无上限重试补齐答案，也不把候选排序分数当成回答概率。

真实本地模型开发验证：原有两组保持 25/29、11/12；之前的 6 个复合/细分属性探针保持 3/6。新增 6 个规范化探针由 4/6 提升到 5/6，改善的是“请问，我喜欢喝啥”不再混入小林的偏好。深层口语改写、复合需求分解及品牌/种类区别仍未解决；不能宣称这次显著提高了整体召回率。

验证状态：memory、桌面类型检查与 Electron 构建通过。第一轮图模块回归为 426 通过、3 跳过；最终完整复查为 423 通过、3 失败、3 跳过，失败涉及 L2 固定视图过期/关闭和 2 秒预算，未开启新功能的用例也出现失败。单独复查有一项恢复通过，但其余仍未通过，尚不能称完整回归成功。本轮临时边界检查为 18/19，未通过项也是 L2 补检后的固定视图失效；正常合并、单次重试、超时终止、来源删除、按问法缓存和身份约束检查通过。预算与校验没有为通过测试而放宽，临时测试程序交付前删除。

## 模型和职责

使用 [BAAI bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base) 的 [Xenova ONNX 转换版本](https://huggingface.co/Xenova/bge-reranker-base)。它联合编码问题和候选正文，输出相关性 logit；不同于仅分别编码文本再比较余弦相似度。它不是关系 NLI，不证明事实真值，也不能自动确定“我”对应哪个实体。

## 文件与功能

| 文件 | 用处 |
| --- | --- |
| `packages/embedding-onnx/src/reranker-manifest.ts` | 固定模型版本、文件大小和校验值 |
| `packages/embedding-onnx/scripts/install-reranker.mjs` | 显式下载并校验；召回时不自动下载 |
| `packages/embedding-onnx/src/onnx-reranker.ts` | 本地成对推理；预加载、有限批次、取消检查、资源释放 |
| `packages/memory/src/graph-core/recall/cross-encoder-selection.ts` | 将同一次评分复用于重排与证据筛选；严格校验 ID 和数值 |
| `packages/memory/src/graph-core/eval/cross-topic-comparison.ts` | 保留 A–F 基线，新增 G/H 真实模型对照与逐候选分数、耗时 |

模型必须在召回预算开始前加载。每次最多处理 256 个候选，默认每批 4 对；每对总长超过 512 tokens 时拒绝整个请求，不静默截断。底层正在执行的 ONNX 批次不能被瞬时打断，但批次前后都检查取消信号，过期结果不会返回或进入评分缓存。忙碌时拒绝新评分，不无限排队。缓存只保留最近一次查询、精确候选 ID/正文与模型版本对应的分数，不持久化正文。

`createCrossEncoderSelection(model, { minLogit })` 返回兼容现有接口的 `reranker` 和 `evidenceSelector`。只接 `reranker` 不会放宽原准入规则；同时接入 `evidenceSelector` 才能让低余弦候选依据独立相关性评分进入证据选择。访问、版本、来源及时间检查仍由现有 L1/L2 接口执行。

当前筛选规则是实验性 logit 门槛，首轮预先固定为 0。它不等于“答案正确概率 50%”，不提供语义充分性证明，也没有独立数据校准。因此它还不能替代完整的可回答性判断。

## 复现

从仓库根目录执行，路径按本机安装情况替换：

```powershell
node packages/embedding-onnx/scripts/install-reranker.mjs --directory '<本地重排模型目录>'
node packages/embedding-onnx/scripts/check-reranker.mjs --directory '<本地重排模型目录>'
node packages/memory/src/graph-core/eval/run-cross-topic-model.mjs --model-dir '<现有向量模型目录>' --reranker-dir '<本地重排模型目录>' --min-logit 0 --report '<报告.json>'
```

只有第一条命令下载公开模型；后两条使用离线模型和合成记忆。未配置 `--reranker-dir` 时仍只跑 A–F。新报告 schema 为 v3，记录模型版本、预加载时间、实验门槛、每批评分耗时及筛选失败。超时或评分器错误不能因恰好返回空集合而被计为“无答案正确”。

## 2026-10-01 真实模型结果

沿用 31 个合成问题、相同候选上限和 2 秒召回预算，评分调用保留默认 300ms 上限，未放宽预算，也未按这些题目调阈值。

| 路线 | 最终证据集合完全匹配 | 多返回错误证据的用例 | 评分失败 |
| --- | --- | --- | --- |
| F：局部宽候选＋原输出规则 | 15/29 | 0 | 0 |
| G：F＋真实模型重排 | 15/29 | 0 | 0 |
| H：真实模型重排＋logit≥0 筛选 | 20/29 | 3 | 0 |

三组候选完整覆盖均为 20/21。权限/删除/版本等既定边界检查均为 31/31，但这不代表“问谁答谁”已经正确：同一用户的记忆中可以合法包含其他人的事实，相关性模型仍会误选。

H 的错误包括：

- “我喜欢喝什么”额外返回小林的饮料偏好。现有实体目标规划不处理句中的单字代词“我”；模型没有替代身份绑定的能力。
- “小林做什么工作”额外返回小林的饮料偏好。相关不等于回答了所问属性。
- 更新用例额外返回另一种饮料偏好。旧版本没有泄露，但返回集合多于题目需要。

H 的 29 次实际评分中位耗时约 157ms，最大约 214ms；这是本机、最多 9 个短候选的小样本，不能推断 64 个长候选也能满足 300ms。保留逐次耗时，不作为稳定服务时延结论。

345 项无模型回归及原有 12 个直接召回用例通过；6 项真实本地运行检查通过。embedding-onnx、memory 类型检查通过；桌面 main 使用既有跨包配置覆盖参数后通过。未执行完整桌面打包或开启真实用户问答实验。

## 结论与下一步

真实模型能补回部分改写问题的相关事实，但当前筛选门槛引入了错误额外证据，故不切换桌面默认策略。下一轮优先补齐可信的当前用户→L1 实体绑定和所问属性约束，再用独立开发集校准筛选策略，并保留独立测试集。不要仅为了消除这里的 3 个错误调整门槛、添加饮料专用规则或固定只返回第一名；这会掩盖多答案与其他主题的缺口。
