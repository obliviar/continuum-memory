# 开放关系原文召回：可行性与第一阶段实施

日期：2026-10-01。本文不安排工期。

## 结论与边界

方案可行：项目的目标是通过提取的关系寻找相关的**已有原文**，不必先把所有关系转成审核通过的正式 Claim。已有 capture、原文跨度、UIE 每请求 schema、开放 assertion 存储都可以复用。

原文不是模型新生成的记忆，但这不保证原文正确、当前仍有效或指向同一个实体。机器仍须检查来源版本、跨度、权限、删除状态，回答仍须保留否定、条件、转述与时间。最终策略将人工审核集中到用户主动请求的、无法确定的身份等同决定及纠错。自动发布表示原文陈述有有效来源，不是已经验证现实事实；旧机器待审项也可据此重新发布，人工决定不被覆盖。

## 第一阶段实现（最新发布策略见文末更新）

| 环节 | 本次行为 |
| --- | --- |
| UIE 目标 | `planUieSchema` 根据文本选择实验、软件、工作领域目标，最多两个领域，保留基础个人目标，按内容增加影视、歌曲、图书目标。正常捕获和空结果重提取使用动态目标；用户手工指定目标不被覆盖。 |
| 开放发现 | 复用 UIE 未知标签与配置的智能提取器开放 assertions。智能提取提示区分 memories 筛选与 graph 导航，允许保留否定、条件、计划、转述。本地规则提供有限的关系回退，任意新关系仍需模型发现或显式提取目标。 |
| 来源入口 | 无图提取结果的有效来源仍能通过原文关键词成为候选，不要求先生成长期记忆条目。 |
| 关联导航 | 将已注册关系和未注册关系统一作为导航线索，以参与者提及连接来源，最多默认三跳。关系标签无需注册、无需审核通过，也不沿路径合成新事实。 |
| 身份处理 | 不自动合并实体。编号精确匹配防止 N1 命中 N11；普通姓名单独重合不作为跨来源桥梁，需要额外共享语境。已知同类物件可作弱连接，路径标记身份不确定；未知类型不能当作已知物件。 |
| 回答材料 | 新协议 `SourceRecallEvidence` 带完整用户消息、来源 ID/版本/hash、跨度、记录时间、owner/agent/session、S1 引用及发现路径。提示词明确原文为不可信历史数据、图路径不是证明。 |
| 调用一致性 | 每次模型调用重新取来源，包括工具删除后的下一轮；验证 owner/agent 及指定 session。提示词超过 4000 token 时丢弃完整条目，不裁剪消息制造失真。 |
| 原有路径 | V3/V4 长期记忆读写仍保留。桌面开放原文模式替代严格 Claim 图提示路径；关闭时恢复原先选择。正式 Claim 与正式 L2 关系的审核及查询协议不变。 |

当前导航本质上是“来源—提及—来源”的有界扩展，路径属于检索结果中的临时路线，不是持久化的正式 L2 逻辑关系。它可以找到语义相似度低、但实体关联强的记忆；尚不具备面向所有关系类别的专门算法选择。

## 权限与开启

桌面记忆设置新增“允许普通历史原文参与聊天”选项，默认关闭，因为开启会授权向当前 API 发送普通历史原文，包含已经保存的历史来源。

需要开启长期记忆；为获得关联扩展，还应开启保存图提取结果。UIE 环境可用时使用动态领域目标；选择智能提取且允许远程请求时，已有智能提取器可发现任意关系措辞，不新增独立远程请求步骤。

启用后不需要逐条确认规范图事实才能沿开放关系找原文，规范图确认面板默认折叠。开启并不修改既有 assertion 的 local-only 字段，而是由独立原文授权路径控制发送。

当前过滤包括：有效来源版本、同 owner/agent（指定 session 时同 session）、拒绝记录、用户明确撤销检索的图审核、关联长期记忆的停止使用/删除/非 allow-remote 分享策略、隐私与密钥/指令风险内容。不可读来源也不能成为桥梁。来源的隐私识别仍依赖已有启发式策略，不能宣称识别所有隐私；高敏感数据不宜直接启用此模式。任何一条关联记忆禁止发送时，保守阻断整条来源。

本次未实现不同 agent 的可共享库选择界面；没有绕过现有 owner/agent 隔离。

### 审核界面修正

增加独立的原文召回状态卡，区分未授权、远程发送禁用、记忆不可用与已经开启。未授权时提供明确标注“向当前 API 发送历史原文”的开启按钮；不自动改动发送策略。

正式 Claim、规范信息关系与正式 L2 发布面板均默认折叠，标为可选管理；未发布 Claim 不再在主概览中计为召回待审项。修正“原文不参与召回”等过时说明，并区分 UIE 默认 Claim 隔离与原文敏感性判断。

修复一个实际权限耦合：对未解析 Claim 选择保留未发布状态，不再把继承的机器 `retrieval.retain=false` 误解成用户撤销原文使用。用户明确拒绝、正式确认时取消检索、删除及分享限制仍生效。界面调整不批准任何事实或合并实体。

## 可直接复现的样例

依次发送以下三条消息并等待捕获完成：

1. 样品S7存放在恒温箱B2。
2. 恒温箱B2使用电源插座P3。
3. 插座P3发生断电。

开启上述原文召回选项后，问“样品S7相关的历史记忆”。来源导航可以找回三条原文。回答可说明这些记录值得一起查看，但不能自动断言“S7已经损坏”或“P3导致S7异常”。发送的是原文及发现路径，不是合成的新事实。

## 还需要改进

1. 当前动态 schema 是有界内容路由，领域包依然是人为定义的目标；不是 UIE 自动发现任意未知关系。开放未知关系发现依靠智能提取或显式目标，本地规则覆盖有限。
2. 当前原文入口基于关键词/提及，导航按查询临时扫描已有数据。纯同义改写、未知别名和海量数据需要来源级 BM25/向量索引与查询侧补提取，而不是继续放宽正式 Claim 审核。
3. L2 后续应对路线分类、排序与跳数选择，处理方向/条件/时间；不能把依赖链当成因果结论。第一阶段只完成有界导航，没有实现完整关系策略引擎。
4. 多人同名、无编号同名物件仍需要按需消歧；当前保守阻断可能漏召回，弱物件连接可能引入噪声。
5. 应分别统计“来源可用率、关联召回质量”和“正式陈述发布率”，不能将不要求确认称为事实100%真实。

## L1 自动发布策略更新

随后按新的 L1 定位调整：模型分数、未知语境不再阻止自动身份处理或陈述发布。已注册、类型相容、有完整原文证据的陈述自动成为 Claim；原始分数保留，未知/否定/条件/转述不会升级成肯定事实。UIE 明确句式的语境判断也不再先检查模型分数，长期记忆候选的独立审核规则不受此改动影响。

明确、非引述的第一人称绑定作用域内的用户身份；其他身份无法确认时建立独立的来源局部实体，不自动按同名或向量合并。已有确定身份绑定仍可复用。无法确定的身份等同决定需要用户主动请求后审核，原有手工身份确认和 alias 决策能力保留；本次没有新增已发布实体的专用合并管理界面。

来源 hash、跨度、参与者是否真实出现在证据中、结构类型和安全内容由机器校验。校验失败不进入常规人工审核；未知关系/类型继续走开放记录路径，并非强行注册为规范 predicate。`accepted/verified` 在新自动发布路径中表示来源对齐，不是现实真值认证；V4 元数据明确记录 `verificationMeaning: source-alignment-not-world-truth`，图提示词也说明这一点。

启动时对旧机器待审记录分批重新发布，检查当前 capture 与来源版本；跳过人工拒绝/暂缓，已发布任务幂等重试，数据清理或重新加载时停止旧存储升级。原始提取记录不被重写，原有隐私与远程分享策略不放宽。
