# 输入端更新后的召回接口对齐

检查基线为 `5ceade5`（包含 `95c91e7` 后台语义工作流和 `457586c` 对话分区）。
保留本地实体向量入口、Claim 片段、候选选择、关系查询规划与局部关系排序。

## 接口检查与修改

| 接口或数据 | 检查结论与处理 |
| --- | --- |
| `GraphRecallRequest.visibleFacts` | 已新增，但上游 L1 用子集生成 manifest，后续却发布完整集合，二者可能不一致。改为完整、与轮次无关的发布视图；在候选和读取处应用可见事实版本集合。 |
| `GraphOpenViewRequest` | 新增同名可选字段，把限制传到固定视图。V4 L1、内存图读器和 L2 桥接均检查；Claim、实体关联事实、Fact 和来源读取继续遵守活性、权限与时间规则。 |
| `knownAt` 与后台写入 | 原先只要仓库更新时间晚于本轮开始，就拒绝召回。显式提供合法可见集合时，允许从当前快照读仍有效的精确版本；未提供集合时仍拒绝历史事务查询。没有恢复已删除/更新的旧事实。 |
| L2 `prepareRelations` | 不再借助每轮 `canRead` 闭包重建并持久化一个事实子集，避免轮次之间改写共享 manifest。保留完整 L1 发布，在种子筛选、关系两端和读取视图处限制可见版本。 |
| 桌面 `beginTurn` | 图写入事实必须已经出现在本轮开始时的 ready 投影，并拥有 published 且允许检索的任务；不能仅依据任务 published 状态。使用精确 Fact ID/版本，缺少有效版本不纳入。 |
| `sourceStatement.qualifiers`、`supplementalQuotations` | 上游已给 L1 返回这些字段，L2 尚未传递。本轮补齐 L2，按精确来源哈希及位置查找已经回读的补充引用，保持原文与补充材料分开。 |
| 基础关系、多参与者 | 已兼容。实体导航遍历 `Claim.atom.args` 的全部实体参数；继续用正式 Claim、原文和完整来源。没有把 V4 的两个兼容锚点误当成全部业务参数。 |
| 五类正式 L2 关系 | 类型与方向约束保持不变。未知基础谓词属于 L1 陈述，不自动成为 `causes`、`entails` 等逻辑关系；来源局部身份与关系审核检查继续生效。 |
| 对话分区 | 本地向量缓存、仓库和创建召回适配器的函数位于独立分区实例内，未发现本次自动合并将它们移出实例。此项是静态检查结论，尚未做切换中的并发验证。 |

原先 `v4-l2-memory.ts` 的冲突同时涉及“本轮可见事实”和“具体澄清原因”；两项行为均保留。
可见集合只会缩小查询范围，不赋予访问权限。空集合代表本轮无可见事实，不能解释成未限制。
所有请求先复制并校验版本引用；同一 Fact 更新版本后，旧可见引用不会匹配新版本。

## 运行顺序与边界

```text
本轮开始：记录已发布事实的精确版本与 knownAt
    → 当前消息持久化、后台提取
    → 准备当前完整图视图（不等待全部后台提取）
    → L1 候选 ∩ 本轮可见版本 ∩ 当前有效性
    → L2 起点与关系两端采用同一限制
    → 已检查端点的关系窗口排序、受限遍历
    → 回读原文及补充引用、再次检查有效性
    → Agent 接收证据
```

后台新增或更新的信息最早下一轮参加正式图召回；输入给本轮模型的用户消息仍然存在于正常聊天上下文。
如果固定读取期间发生更新或撤回，仍拒绝失效视图；运行时沿用上游已有重试/暂不可用处理。
本轮未实现跨任意历史版本读取，也不保证高频写入下每次召回都能成功。

上游还有独立的 `sourceRecall` 原文引用通道。启用 `openSourceRecallEnabled` 时，桌面不选择正式图召回配置；
这条原文通道不等于已走“实体向量 → L1 → L2”，也不因路径相似而获得关系证明。
本次没有改变输入端的模式选择、自动发布、API 工作流、Skill 或文档工具，也没有迁移本地数据库。

## 验证范围

按当前约定只做 memory、core 与桌面主进程的 TypeScript 静态检查和差异检查，
不运行单元测试、模型测评或桌面程序。上述时序、分区切换、补充材料输出及预算边界还需要后续回归验证。
