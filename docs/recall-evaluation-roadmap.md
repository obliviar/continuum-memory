后续一轮已增加实体局部宽候选、独立证据判断接口和 F 对照，见 [宽候选说明](wide-local-candidates.md)。本文下方 A–E 数字保留为前一轮基线记录；最新候选覆盖为 E 7/21、F 20/21，最终严格输出匹配均为 15/29。

本轮落实六阶段规划的第 1、2 步基础设施及第 3 步接口。保留桌面默认的“实体向量定位 → 局部 Claim → 受限 L2 遍历”路径，不因小样本分数自动更换默认策略。第 4–6 步的新增关系规划、边语义重排和可回答性校准尚未在本轮实现。

## 统一测试入口

从仓库根目录运行（替换两个绝对路径）：

```powershell
node packages/memory/src/graph-core/eval/run-cross-topic-model.mjs --model-dir '<已安装模型目录>' --report '<报告.json>'
```

仅加载已安装模型，不下载模型、不读写真实用户记忆。夹具在 `packages/memory/src/graph-core/fixtures/cross-topic-recall.ts`，含 11 个事实、2 个显式实体、31 个问题。覆盖饮食、住址、职业、项目、时间，以及改写、他人、否定、无答案、多答案、更新、删除、撤回和权限变化。这是人工可复核的合成夹具，尚不是经过独立人工审核的真实用户基准。

| 路线 | 检索入口 | 重排 |
| --- | --- | --- |
| A | 关键词 BM25 | 关闭 |
| B | 事实向量 | 关闭 |
| C | 关键词＋事实向量，RRF 融合 | 关闭 |
| D | C＋现有结构化规则 | 关闭 |
| E | 实体向量 → 实体关联的局部事实向量 | 关闭 |

所有路线使用相同问题、预期证据、访问/时间约束和最终预算。候选池上限 64，通常最终事实最多 4；多答案截断用例单独设为 1。E 另外限制实体入口为 4，并且不隐式回退到全局关键词/事实检索。每题轮换路线运行顺序，文档向量准备与查询耗时分开；查询向量每次实际推理。

报告的严格命中要求“返回事实集合与预期集合相同”，不是生成答案准确率。权限拒绝和刻意限制输出数量的用例不计入普通质量分母，因此每路线有 29 个质量用例、31 个边界用例。错误返回会降低质量，并单列 `errors`；没有泄露证据并不等于成功回答。保留无答案误召回、错误人物与时间表达失败，不按结果修改标签或调阈值。

## 诊断记录

`V4GraphMemoryOptions.diagnostics` 是可选的可信本地观察接口，默认无观察器。按阶段记录授权后的事实 ID、累计耗时和检索范围：

1. `eligibility`：通过来源、版本、权限和时间检查。
2. `entity-entry`：实体入口对应的局部候选（仅 E）。
3. `retrieval`：检索得到的候选。
4. `selection`：进入最终事实/图起点的候选。
5. `delivery`：证据组装及最后复查后的事实。

测试报告根据正确证据最早在哪一层消失标记 `missing.stage`，并列出多返回的 `unexpected`。若某阶段尚未执行而请求已失败，则标为未观察/错误，不能猜测为排序问题。观察器不会接收来源正文或被拒绝记录的 ID，数据也不会自动加入模型提示词。诊断回调的异常不会改变召回。真实应用若持久化诊断，应由可信宿主按用户隔离和保留策略保存。

## 候选与最终选择分离

`recall/candidate-selection.ts` 提供 `candidateSelection`：

- `candidateLimit`：宽候选池，默认 64，允许 1–256。
- `reranker`：可替换的可信本地评分器，接收已授权候选的 ID、正文和查询。
- `timeoutMs`：默认最多 300ms，且不能超过剩余预算的一半。

评分器只能返回同一候选集合的完整排序，禁止新增 ID、重复 ID 或非有限分数。失败/超时保留原排序并记录原因。没有评分器时严格保留原顺序；本轮没有安装具体重排模型。排序分数不解释为答案概率。L2 将成功重排后的顺序转换为接口需要的有界优先级，再按最终起点数量截断。

候选池数量、实体入口数量、最终起点数量、L2 节点/边/跳数预算及证据 token 预算各自控制。被截断会记录在 trace 中；不能把第一名或有限预算内找到的结果称为完整答案。

## 性能与索引边界

当前 BM25 使用内存倒排表；当前图召回入口仍会为请求准备符合约束的文档和索引。向量使用 exact-flat，逐条计算点积再排序，评分复杂度 O(N×d)，排序另有成本。实体入口减少的是后续参与局部 Claim 检索的范围，不代表请求全过程没有全量准备/校验。

报告含 `indexScaling`：100、1,000、10,000 条规模，分别记录建索引耗时和 5 次搜索耗时。使用真实模型向量、重复合成文本扩充规模，不用于质量评估；不含模型推理、来源校验和图遍历，不能冒充端到端性能或生产规模结论。当前未引入 ANN。未来增加 ANN 时，应单独对照 exact-flat 的速度和漏检，而非同时更换重排器。

## 后续顺序

1. 人工复核合成标签，补充独立真实样例，扩大实体数量及 L2 关系问题；当前夹具不足以验证大实体库的入口漏检。
2. 先解决候选入口漏检，再在相同候选集合上接入具体重排器，保留无重排对照。当前事实向量仍沿用原有 0.8 准入阈值；分离候选池不等于已经放宽该阈值。后续将更宽的局部 Top-K 候选与最终可回答性判断分开实验，禁止只降低阈值后直接输出。当前统计先用于定位缺口，不用于阈值校准。
3. 完善问题到关系类型、方向、时间范围的映射，解决周期时间表达等已暴露的问题。
4. 只对合格边做端点语义排序，同一跳按优先级探索，保留冲突和竞争解释检查。
5. 增加证据可回答性判定；独立数据校准后再决定回答/澄清/证据不足，不将向量分数称为概率。

模型报告是诊断结果；实现边界由 `candidate-selection-regression.ts` 及原有 L1/L2 回归共同验证。统一无模型检查入口仍为 `eval/run-direct-recall.mjs`，新增检查已纳入失败退出码。
