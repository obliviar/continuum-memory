# L1 graph fact review and publication

Smart extraction saves raw UIE output first. Identity and predicate normalization runs next. A separate graph review records `approved`, `rejected`, or `pending` with a reason, source ID and revision, model score, reviewer, user-confirmation flag, sensitivity, and share policy. The retrieval assessment is independent of proactive preference use: source-backed entity facts can be retained for search without becoming user preferences. Proactive preference use requires an explicit user confirmation and selection.

Approved, resolved candidates enter an encrypted publication outbox. The writer commits an Episode, active V4 Fact, direct evidence link, auditable Fact version, and domain event in one V4 repository transaction. Only after the exact version exists does it publish a graph-core-shaped `GraphClaimRecord` and its context in the encrypted L1 store. Entity-to-entity edges are derived from that Claim and carry its `claimRef`; literals do not become entity edges. The Claim retains entity refs, predicate roles, evidence span and source hash, valid time and original time text, polarity, modality, condition, privacy, and accepted review provenance.

The outbox is persisted before either write. If V4 persistence fails, no Claim is published. If L1 persistence fails after V4 commits, the task remains for retry. Startup retries outstanding tasks, validates the exact active Fact version and available evidence, and uses deterministic IDs to avoid duplicates. Source truncation and memory clear remove local L1 claims, edges, tasks, and reviews.

The memory manager exposes pending graph reviews with source evidence, a required reason, and separate checkboxes for retrieval retention and proactive preference use. Before approval, the reviewer explicitly chooses the identity of each involved mention (an existing same-scope, same-type entity or a new independent entity) and reviews negation, condition, time, and speaker attribution. Unknown is a deliberate choice, not an automatic positive assertion. The host rejects incomplete extraction, invalid evidence/date/identity choices, and changed source revisions. These decisions are saved on the durable publication task and applied to both the V4 Fact and L1 Claim; the original UIE result stays untouched. Manual confirmation keeps the source and privacy fields and does not replace the original model score.

The graph-core package now exists under `packages/memory/src/graph-core`. The encrypted Claim/context/edge store is the publication outbox, and `createGraphSemanticRepository` publishes a complete encrypted `GraphSemanticBundle` through the `GraphSemanticWritePort` contract after the exact V4 version exists. A separate encrypted `GraphProjectionSnapshot` is then published with a deterministic ready manifest and semantic `has-argument` edges from each accepted Claim to its entity arguments. Its snapshot API returns no view if the semantic bundle, exact V4 revision, source evidence, or projection contents are stale. The old entity-to-entity edges remain navigation conveniences rather than independent facts. Failed bundle or projection writes leave the task pending for retry. Startup rebuilds the bundle and view from accepted Claims; source removal and memory clear also schedule a rebuild. The direct V4 graph recall adapter reads only Claims in this ready view marked for retrieval, rechecks the live V4 Fact, exact version, source hash, and access policy, and returns source evidence. Unknown polarity, time, modality, or conditions remain explicit in the evidence and make coverage incomplete; they do not establish a current positive fact. L2 relation traversal and inference remain separate capabilities.

L1 contexts now identify a normalized discourse frame rather than one publication task. The stable key includes the exact owner/agent/session scope, speaker attribution, and normalized condition text. Unconditional self assertions in the same scope therefore share an actual context across Claims and sources; distinct conditions do not. Reported speech is shared only within the same source revision because a speaker name is not a verified cross-source identity. An unresolved speaker or condition remains isolated to its Claim, and an unresolved condition has an `unknown` scenario rather than being silently treated as actual. Negation and valid time remain Claim attributes, not context identity. The context record derives its live provenance sources and strictest access policy from its member Claims. On load, previously published per-task context IDs are migrated into this frame scheme before the semantic bundle is rebuilt. L2 still requires both endpoints to reference the exact same context version; sharing a context makes a relation eligible for review, not true by itself.

Local UIE output now enters the same raw extraction protocol before its eight-item personal-memory selection. Its original payload and code-point offsets are retained; graph spans use UTF-16. Unresolved UIE context is marked for review. A reviewer can establish stable independent IDs scoped to the source revision and mention, or select an exact existing ID; this never merges people or organizations merely because their names match. Unknown predicates and incompatible types still require separate review. The existing runtime rollout gate remains `CONTINUUM_GRAPH_MEMORY=1`; graph recall takes the place of the legacy prompt recall while enabled.
