# 直接事实召回回归测评 v1

本测评验证真实 V4 仓库接口、L1 映射及现有 BM25 召回，不调用模型，不读取用户记忆。
记忆和预期证据为固定合成案例，尚未经过用户人工审核；不是公开 benchmark，也不衡量最终回答质量。

## 运行

在仓库根目录，Node 24+：

```powershell
node packages/memory/src/graph-core/eval/run-direct-recall.mjs
```

输出 JSON 包含每题预期证据、实际证据、遗漏和多召回，以及可接入数量和排除原因。

`acceptedL1` 为新增原生实体 L1 接入回归：18 项检查使用真实写入、语义发布、投影、召回和
固定读取实现，覆盖别名、撤回、删除、精确版本、来源范围、未知语义、隔离及 L2 准备接口。
它使用合成数据和内存持久层，不代表真实用户问答质量或 Electron 实际窗口验收。
需要保存时，先设置 `GRAPH_RECALL_REPORT_PATH` 为输出文件完整路径。
设置 `GRAPH_RECALL_STRICT=1` 后要求全部问题的证据集合与预期完全一致，否则退出码为 1。
默认模式检查来源/版本完整性、权限隔离、11 个已修复的原始案例、额外词法检查及混合召回接线检查；已声明的无关键词语义改写缺口仍作为质量失败记录。
默认退出码 0 **不表示所有召回质量项目通过**，必须查看 `qualityPassed`。

正常环境也可在 packages/memory 中运行：

```powershell
pnpm exec vitest run src/graph-core/eval/direct-recall-regression.test.ts src/graph-core/recall/direct-semantic.test.ts src/graph-core/adapters/v4-input-diagnostics.test.ts --no-file-parallelism --no-cache
```

## 2026-09-27 实测基线

12 个案例中，严格证据集合匹配 7 个，未匹配 5 个。

| 案例 | 结果 |
|---|---|
| 喜欢喝绿茶 | 目标命中，但额外召回“不喝牛奶” |
| 绿茶是不是喜欢的饮料 | 目标命中，但额外召回“不喝牛奶” |
| 不喝牛奶 | 目标命中，但额外召回“喜欢喝绿茶” |
| 更新为喜欢喝咖啡 | 命中新版本，但额外召回“不喝牛奶” |
| 删除来源 | 不再返回被删除来源支持的事实 |
| 宠物名字（未存储） | 返回空集合 |
| 不同用户 | 拒绝访问 |
| 不同 Agent | 拒绝访问 |
| 不同会话 | 不串数据 |
| 禁止远程分享 | 不返回本地限定事实 |
| 缺少有效时间 | 排除该事实 |
| 偏爱的饮品是哪种 | 无共同关键词，漏召回绿茶事实 |

以上 7/12 是这组小样本的严格集合匹配计数，不能推广成真实用户问答准确率。
`knownGap` 仅为案例备注；所有未通过项都保留在报告里，未修改预期来追随实现。

下一步可先处理弱相关候选过滤，再比较向量/结构化入口对改写召回的改善。
实体推导、L2 多跳和完整规则证明不属于本套直接事实用例。


## 弱相关候选修复后的对照

原始 12 题和预期证据均未修改。启用 `direct-lexical-bigram-v1` 后，严格证据集合匹配由
7/12 提升为 11/12。四个“只因共享单字而多召回”的案例均恢复为预期集合；无共同关键词的
语义改写仍为漏召回，不计为通过，`GRAPH_RECALL_STRICT=1` 仍会返回失败。

新的分词仅用于 direct graph 入口，V3/V4 公共分词及其他图遍历入口不变：
- 多字中文使用连续双字片段，不依靠单个汉字重合。
- 标点、空白和拉丁文形成边界，不跨边界拼接双字。
- 去掉有限问句包装词和英文功能词，减少虚词造成的误召回。
- 明确的单汉字查询仍保留单字匹配。
- 不因查询带有否定词而删除正向事实，同一对象的相反证据可以一起召回。

另加 11 个独立词法检查，覆盖其他主题、英文虚词、全角文本、单字、标点边界、多个相关
结果和相反事实。这只是词法过滤修复，不是语义理解；短语仅共享双字仍可能误召回，
同义表达和单字问题的精确性也需要更大测试集评估。
报告的 `lexicalChecks` 单列新增检查，避免与原始 12 题合并后混淆前后比较。

## 本地向量入口接入

桌面图问答复用已启用且校验通过的本地 ONNX 语义模型与 V4 加密向量缓存。
仅对已通过权限、来源、精确版本和时间检查的事实查缓存；按事实 ID、模型指纹、
当前 canonicalText 匹配，不接受旧文本向量。没有向量的事实仍参加 BM25 检索。
请求内只计算问题向量，记忆向量仍由已有后台准备任务生成，不在召回中批量生成。

向量通道以暂定 cosine >= 0.8 准入，与 BM25 按 RRF（k=60）合并、去重。
0.8 尚未基于真实模型评测校准，不是相关性概率；向量相似不构成关系或规则证据。
问题向量等待最多 500ms，且不超过剩余预算的一半；失败、超时、未就绪时保留
BM25 结果，trace 标明状态。模型的底层运算可能继续，但迟到结果不会进入本次回答。
启用语义通道后，缓存缺失或降级均标记 incomplete；原有节点与证据预算继续生效。

新增 `hybridIntegration` 单列 30 项**测试向量接线与边界检查**，包括跨关键词候选、
双入口合并、阈值拒答、部分缓存、模型/维度/内容失配、来源删除、访问撤销和预算。
这里的向量是显式构造的二维数据，只证明接线与边界行为，不能证明真实模型能理解改写。
原有 12 题仍用无模型 BM25 基线，保留 11/12 和 semantic-rewrite 的未通过记录。
后续应启用本地模型，等待 V4 向量准备完成，在同一批人工确认的记忆/问题上对比两种入口，
记录改写命中、多召回、无答案误召回、缓存覆盖率和耗时，再决定正式阈值。

## 真实本地模型对照入口（模型未安装时不执行）

先在桌面应用安装并校验本地语义模型，然后在仓库根目录运行（Node 24+）：

```powershell
node packages/memory/src/graph-core/eval/run-direct-model.mjs --model-dir "C:\实际数据目录\models\memory" --report ".\outputs\direct-model-comparison.json"
```

`--model-dir` 指向包含 `bge-small-zh-v1.5.manifest.json` 的缓存目录。
也支持 `GRAPH_RECALL_MODEL_DIR`；均未指定时使用 Windows 应用默认数据目录。
脚本只使用已安装的本地模型，通过正式 ONNX 适配器校验文件和运行探针，不下载、不调用
远程 API、不读写用户记忆库。测试向量缓存在内存中，退出后释放，不修改桌面缓存。

输出包括：
- 原样保留的 12 题 BM25 基线，以及逐题相同预期证据下的混合召回结果。
- 0.70、0.75、0.80、0.85 四个准入门槛的探索性对照；不自动修改生产配置。
- 漏召回、多召回、无答案误召回、权限/证据失败、改善与退化，以及语义实际参与和回退情况。
- 模型初始化、事实向量准备与请求耗时分开记录。问题向量每次实时计算，不缓存。
  请求仍使用生产的 500ms 向量等待上限、2s 总预算；超时如实记录，迟到推理结束后才跑下一题。

退出码：`0` 表示当前生产门槛 0.8 下全部预期证据匹配且语义通道实际参与、无降级；
`1` 表示质量门禁未通过或执行失败；`2` 表示模型缺失/完整性校验失败，未执行测评。
`status: completed` 只表示执行结束，还需查看 `qualityGatePassed`。
模型缺失时报告为 `not-run`，质量分数为空，不用测试向量填充真实结果。

这是小规模合成开发集，尚未人工审核，不能作为独立验证集或泛化准确率。
模型已经预热，且事实向量事先准备齐全，因此延迟不包含启动和后台建索引，不能当成冷启动
或真实用户全量记忆延迟。不同门槛按固定顺序各跑一次，耗时仅作诊断，不作性能优劣结论。
报告保留每题 trace 中可用向量数；真实库缓存覆盖率仍需另测。

普通无模型回归另加 `modelHarness`，用明确标记的测试向量检查对照脚本是否正确计算和
报告退化。这些结果绝不并入真实模型质量报告。

## L1 固定视图回归

同一无模型入口还运行 `l1Views`：19 项检查覆盖固定 Claim/Fact/Source 回读、重启恢复、
两个实例的 CAS 冲突、旧格式迁移、来源删除或修改、权限撤销、伪造视图、时间过滤、
写入失败和节点/证据预算，并验证正式 L2 读取器绑定真实 L1 视图后随其关闭而失效。
这仅验证 L2 绑定边界，尚无桌面真实关系问答验收。测评用内存检查点实际保存和回读
发布内容，不再用丢弃写入的占位 persistence，预期证据没有修改。

## L2 宿主接入回归

报告新增 `l2Host`，25 项检查覆盖原因/结果/先前/后续的类型和方向、关系持久化重载、
空库和未采纳候选不产生关系、不同来源不合并上下文、来源变动与删除、权限隔离、
零跳数、输出预算和提示词端点校验。单进程入口会调用真实提示词构建器；Vitest 中的
memory 测试不跨包加载提示词，该检查仅在单进程入口执行。
另覆盖同一宿主多个仓库实例的并发发布、旧实例禁止覆盖/清除新版本、异步校验期间的
外部失效与输入修改、写入失败保留旧记录，以及当前实例正常失效/清除。

测试关系为明确编写的合成来源陈述，绝不从 NLI 或向量分数自动生成；不代表用户库
已经拥有关系，也未测试最终远程 LLM 生成的答案。L1 映射升级到 v2 后，基线问题和
预期证据保持不变；旧快照需重建，旧关系需复核，不能自动迁移引用。

## L2 删除联动回归

同一单进程入口新增 `l2Lifecycle`，12 项检查实际加载桌面的 `withGraphSourceInvalidation`，
运行 V4 生命周期与 L2 级联清理：共享来源下的事实删除、彻底清除、来源删除、普通更新、
暂时停用、无 L1 的启动补清理及幂等、启动不改写正常快照、L2/V4 分别写入失败、重启
不复活关系、带冒号的事实 ID 隔离和无效 V4 输入拒绝。测试使用合成数据及内存持久化，
验证真实写入调用顺序；没有启动 Electron 或改动用户实际记忆库。

## L2 显式复核回归

`l2Review` 的 13 项合成测试覆盖：预览不恢复 L2、确认后保留精确关系并恢复问答/重启
读取、来源变更阻塞、预览后 V4 或 L2 变化拒绝、返回报告篡改隔离、凭据并发单次使用、
未知与过期凭据、范围隔离、权限撤销、操作者/说明必填、候选不自动采纳及保存失败。
该测试验证宿主复核协议，不证明关系内容经真实人工审核，也不替代桌面 UI 验收。

## 桌面复核入口

同一单进程入口新增 `desktopReview` 的 9 项检查，直接调用桌面控制器及真实复核服务：
预览/发布、固定操作身份、前端参数限制、刷新与重载撤销、来源变化、阻塞提示、并发
确认、同步失败和仓库未就绪。合成测试不会调用真实 Electron IPC 或用户数据。

另运行实际编译的 Vue 组件交互检查：

```powershell
node apps/continuum-memory-electron/src/main/graph-relation-review-renderer-regression.mjs
```

6 项检查覆盖说明/勾选的按钮门槛、发布参数、文本转义、阻塞/过期/空报告与错误提示。
使用内存渲染器及模拟 IPC；验证事件与状态，不代表真实 Electron 窗口的视觉验收。
