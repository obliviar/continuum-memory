# 开放断言图：存储、审核与检索

当前图支持三种记录：原文 `information`、开放断言 `openAssertions`、规范化 `claims`。未注册的关系和不符合规范谓词角色类型的候选可以进入开放断言；不再要求增加领域 schema 后才能保存关系结构。

## 提取

- UIE 的未知根标签保留为实体类型候选，不再被固定标签列表过滤。
- 本地 UIE 接口支持 `extract(text, schema)`，或者在创建提取器时配置 `schema`。Python 工作进程在每次请求前重设 schema，下一次普通请求恢复默认目标。自定义目标记录在提取 run 的 `rawOutput.extractionSchema`。
- 桌面端允许选择已有原文，填写 `样品→存放位置；设备→故障` 等目标进行本地重新提取。动态目标没有修改全局谓词语义。
- 本地句式规则补充明确关系表达、存放/依赖/连接句式及多个参与者的放置事件。UIE 失败时仍能生成这些开放候选，并保留原有规则记忆。规则分数表示句式及位置匹配，不表示现实真实性；符合原文语境准入策略的候选可自动用于本地关联查询，但不自动获得用户确认。
- 已启用的智能提取模式可输出任意领域的 `graph.assertions`，包含原文关系短语、参与对象、角色和语境。本次没有额外启用外部模型调用。
- 没有成功抽取的内容仍保存为原文节点。当前本地原文搜索为文本匹配；开放断言支持查询时的本地语境向量辅助排序，尚无独立持久化向量索引。UIE 及局部句式规则并不保证发现所有未知关系。

## 开放断言结构

`GraphOpenAssertionRecord` 包含稳定断言引用、scope、精确 capture 来源版本及哈希、提取来源、关系原文、证据位置、原文片段、任意数量的参与对象、字面属性、context、审核状态、模型分数与隐私策略。关系词位置可选：UIE schema 关系标签不一定是原文中的字面短语，因此不得伪造其原文位置。

参与对象使用 `mention` 引用，其 ID 由 capture、版本和位置决定。跨原文同名提及不会合并成规范 Entity。`typeCandidate` 保留模型建议，未知类型可以使用 `unknown`。一个事件可连接三方或更多参与对象。

开放断言经用户确认，或获得仅用于本地导航的自动准入后，L1 图视图生成 `open-participant` 和 `open-evidence` 连接。它不会写入 V4 规范 Fact，也不会成为已有规则推理器的 Claim 前提。`inferenceAllowed=false`、`sharePolicy=local-only`。

## 审核与生命周期

用户审核状态仍为 `candidate`、`accepted` 或 `rejected`；自动准入不会伪造 `accepted` 或用户审核记录。新增 `admission.localNavigation` 为 `automatic`、`candidate-only` 或 `blocked`，记录策略版本和原因。它始终禁止身份合并、Claim 发布、主动偏好使用和远程分享。

`sourceContext` 从精确 capture 回溯证据前后最多 400 个 UTF-16 单位，整体最多 1600 单位，记录原文位置及是否截断。当前只回溯同一用户消息，不自动解析历史会话指代或被引述者。候选的否定、条件、时间和说话者字段不被覆盖成确定值。

自动本地导航要求完整有效提取、精确原文关系位置、至少 0.85 的提取分数以及受支持的提取来源。条件、否定、转述、疑问、意向、指令、含糊指代、敏感来源、窗口截断和非字面 schema 标签保留为按需核实候选。检查是保守的启发式规则，分数门槛不等于真实性概率，不保证检测所有歧义。

桌面端将开放记录管理默认折叠，自动准入项不计入必须处理的待审核量，不确定开放候选单独计数。查询默认不包含不确定候选；用户可勾选显示，结果明确标注未核实并保留原文语境，可在查询时按需确认。正式 Claim 和 L2 的现有审核门槛未改变。

仅完整、源哈希正确且能唯一对应当前 capture 或精确 capture task 分段的提取可以投影。分段位置转换为完整原文的 UTF-16 位置，禁止随意按子串猜偏移。修改、删除来源，清理提取，或者撤销审核，会立即使旧图视图不可读；同步后删除相应连接。来源相同、参与对象、关系、语境和证据一致的重试复用断言 ID 及审核决定。语境或结构改变会生成新的审核项。

run 与审核记录保存在 `graph-extractions.enc`；图快照和连接分别保存到 `graph-semantic.enc`、`graph-l1-projection.enc`。均位于桌面端当前 `userDataDir`，使用现有加密持久化。旧版本的 v1 payload 可读取，无需清空记忆。

## 本地关联检索

`searchOpenAssertions` 默认检索已确认及自动导航准入记录，检查 owner/agent/session 和 sensitivity。先用原文或提及文本定位，再通过相同提及文本提出关联候选；明确不相容的类型候选不作同名扩展。检索深度最多三跳、结果最多一百条；桌面端使用两跳、二十条。`includeCandidates` 允许单独展示未核实候选，不改变它们的准入或审核状态。

返回 `text-match`、`mention-text-candidate` 或 `context-vector-candidate`、核实级别、跳数、上一条记录和关联提及文本。跳数表示断言之间的关联扩展次数，而非底层参与者边数。相同提及文本仅表示可能相关，不证明对象身份一致。原文与路径一起展示，不生成“样品已损坏”等新结论。拒绝记录及失效来源不参与检索；原文仍可单独搜索并标注为来源记录。

`searchOpenAssertionsWithContext` 使用已启用、通过完整性验证的本地 BGE 模型，对“参与对象＋关系＋原文语境”编码，辅助排序，并以最多五个语义种子进行有限关联扩展。默认比较 32 条记录，最多 64 条；优先文本命中，超出预算时标注不完整。语义候选的 0.6 相似度门槛只是探索性相关性筛选，未校准，不用于自动审核或确定身份。已有向量可比较相邻记录的语境相似度，但不会因此合并 mention。

无本地语义模型、模型禁用、推理失败或无效向量时回退文本查询，不自动下载、不请求外部模型、不使用哈希向量冒充语义向量。桌面端最多缓存 256 条向量于内存，重新初始化及强清除时清空；不新增向量持久化。异步查询完成前再次检查当前图 manifest，来源或审核变化时拒绝旧结果。

规范 Claim 和已发布 L2 逻辑关系继续走已有聊天召回链路。本次新增的是开放结构与本地查询通道；开放断言不会自动发送到聊天模型，也未作为 Erlangshen L2 关系判断的端点。关系同义映射、领域 schema 自动学习以及开放断言的 L2 端点接入需要后续独立实现。

## 验证

单元与集成测试覆盖未知关系/类型、多参与者、精确来源分段、同名提及不合并、关联检索、撤销、来源变更与删除、保存失败及 malformed 提取。真实本机 UIE-base 测试覆盖原有 Claim 发布，以及新领域开放断言的捕获、加密入图、关联查询、重载、动态 schema 与恢复默认 schema。Vue 组件交互测试验证确认 IPC 可克隆、错误可见、关联说明和补充目标提交。

2026-09-30 小规模设计样例对照：12 条中 6 条明确关系自动获得本地导航权限，6 条风险样例保留为候选，风险自动通过 0/6。这是构造样例验证，不是实际对话审核降低率或语义向量准确率。向量路线测试使用可控测试向量验证排序、扩展和权限隔离；本机未发现已安装的 BGE，因此不能声称真实语义向量的改善幅度已验证。
