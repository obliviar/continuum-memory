# 开放关系优先的 L1 提取（2026-10-01）

## 本轮范围

只调整提取入口和 L1 来源对齐，不修改 L2 的分类、算法或推理。本项目的“推理”指发现相关历史记忆，不指生成新事实。

## 提取链路

桌面设置新增“开放关系优先”模式：本地规则产生长期记忆候选；当前配置的聊天 API 独立发现实体提及、任意原文关系措辞、多参与者事件和语境，输出开放 assertions。开放结果保存后，再执行可关闭的本地 UIE 领域补充。UIE 不再是所有关系进入图的必经入口。

“智能长期记忆”模式复用同一次 API 请求，分别输出开放 graph 与长期 memories；长期记忆筛选不得筛掉图中的否定、计划、条件、转述关系。“规则”和“UIE”模式仍可离线使用，未默默变成远程模式。

UIE 本身仍依赖 schema。解决方案不是声称 UIE 能无 schema 提取，而是把任意关系发现从 UIE 分离；UIE 的动态领域目标继续作为补充能力。开放提取仍要求 JSON 字段结构，但不要求预定义关系类别、实体类型或领域目标。

## L1 保存规则

- 开放关系走既有开放记录库和投影，不强行转为规范 predicate Claim。
- 实体文本、关系措辞和跨度必须对应原文；开放 API 关系必须给 relationSpan，且参与者在 evidenceSpan 内。
- 保存模型分数、未知语境和否定/条件/计划/转述信息；低分和关系词不在注册表内，不单独形成人工审核门槛。
- 开放记录本地导航策略升级为 v2：取消模型名称/UIE 来源要求和 0.85 分数门槛；语境限定与局部代词仅作标注，不自动建立跨来源身份关系。敏感内容、无原文措辞、证据错误与用户撤销仍限制使用。
- 保留来源、版本、完整模型输出和错误诊断。身份不确定仍保持来源局部提及，不自动按同名合并。
- 进入图表示原文有这个表达，不表示表达为现实真值；召回仍返回原文证据。未修改规范 Claim 与开放记录的不同语义。

## 如何启用

重新启动桌面程序，在记忆设置选择“开放关系优先”，配置当前 API；可关闭“本地 UIE 领域补充”验证提取不依赖 UIE。提取与历史原文参与聊天是不同授权，后者仍由独立开关控制。

历史的无关系记录可点击“重新提取无事实记录”；开放/智能模式使用开放提取，离线模式使用 UIE，每次最多五条。已有关系记录不自动全部重跑。配置指纹包含新管线版本、UIE 补充选项和开放模式模型配置，避免新任务沿用旧处理标记。

远程提取前检查整段来源：普通且允许发送才调用；私密、密钥、不安全内容保持本地，不因开启开放模式自动授权。旧设置保持原模式，不默认增加 API 请求。

## 边界

无 API、权限阻止或模型失败时保留规则结果和可用 UIE 补充，但本地规则不能保证覆盖任意陌生措辞。模型也可能漏提或给错跨度，机器校验会拒绝无证据结果；解除类别限制不等于无限召回率。真实 API 提取效果需要配置模型后以业务样例评测；自动化测试使用模拟响应，不代表真实模型质量。

## 本轮验证

新增开放提取测试六项通过，包含陌生关系、低分、独立 graph 通道、缺失/错误关系跨度、发送权限、API 失败回退，以及提取到开放 L1 再到原文召回的连通验证。桌面回归62项通过、5项跳过；memory 最后一次回归（排除已在前一轮通过的两项耗时校准测试）817项通过、9项跳过。memory 与桌面前后端类型检查、Electron 生产构建通过。真实 API/UIE 模型效果未在本轮验证。
