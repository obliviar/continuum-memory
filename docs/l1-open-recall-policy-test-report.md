# 开放 L1 低审核策略：小规模对照测试

日期：2026-10-01。结论：在构造样例中，新策略可消除因关系未知、语境限定或低分引起的入库确认要求，并明显提高来源检索覆盖；开放图仍能扩展到关键词未直接命中的记忆。但放宽准入和沿用现有匹配方式会增加无关结果，需要编号精确匹配、同名语境重排和语义检索后再决定默认启用。

## 测试范围及口径

本次是评估代码中的离线策略原型，没有修改桌面生产审核、实际聊天提示词或用户记忆库。

主要样例共 26 条来源：24 条人工构造的关系提取观测（8 条明确关系、8 条否定/假设/转述/疑问/计划/引述/代词样例、4 条非字面 schema 标签、4 条低分），加 2 条没有提取结构的原文。主测试包含 28 个查询和 32 个预先指定的相关“查询—来源”对；另测同名压力、用户拒绝、删除、修改与不同 agent。

这些人工构造的观测通过真实提取协议解析、capture 保存、来源校验及开放断言投影。它们不代表 UIE 在真实对话中的提取准确率。本次没有运行真实 UIE 模型、语义向量模型或 NLI，也没有测试新策略的远程发送权限和实际回答准确率。

对照组运行当前 `assessOpenNavigation`/`canNavigateOpenAssertion` 和 `searchOpenAssertions`，不先接受候选。原型组仅在测试内允许有效投影参与开放检索，保留候选状态、不合并实体、不生成 Claim，组合基于完整来源的文字匹配回退。两组使用相同语料、scope、查询与深度/结果限制。权限检查与拒绝处理属于测试适配器，尚不是生产实现。

“审核量”指 24 条开放观测中，在旧策略下必须确认后才能取得自动导航资格的数量；不是桌面实际待办计数。现有开放管理默认折叠，未准入记录也可能只是不参与召回，因此不能声称已经让用户点击次数实测下降 100%。本次也没有比较整套 V3/V4 生产聊天的召回率。

## 主要结果

| 指标 | 当前开放导航策略 | 新策略原型 |
| --- | ---: | ---: |
| 不确认即可参与开放导航的观测 | 8 / 24 | 24 / 24 |
| 取得导航资格所需确认 | 16 / 24 | 0 / 24 |
| 命中相关来源对 | 14 / 32 | 31 / 32 |
| 来源证据召回率 | 43.75% | 96.88% |
| 返回来源数（跨查询累计） | 14 | 35 |
| 来源证据准确率 | 100% | 88.57% |

确认需求在这组构造样例下降 100%，是策略定义与有效观测条件下的结果；并不预测真实用户纠错和澄清的频率。代词样例能被存储但未纳入主检索查询，不能根据它推断身份消歧效果。

其中新原型的增益包含原文回退和准入放宽，不能全部归因于图。单独的扩展消融确认：

- 查询“样品S7”，深度 0 只找到存放记录，深度 1 额外找到“恒温箱B2发生故障”，即通过存放位置导航到关联设备信息。
- 查询“模块A”，深度 0 只找到依赖记录，深度 1 额外找到“模块B连接到设备D”。

这两条结果证明现有开放参与者结构能提供关键词之外的导航价值；未运行完整 L2 自动连接算法，不能声称所有复杂图遍历已经有效。

## 有效性检查

5 个新增评估用例加 17 个现有相关回归用例，共 22 个通过；新评估最后一次修改后单独复跑 5 个通过。memory 包 TypeScript 检查通过。

- 新原型输出正文逐项匹配原始来源，否定、条件、计划、引用和疑问保持原文表达，没有改写成肯定事实。
- 三参与者事件保留全部对象；未确定语境保持未知，不伪造已审核状态。
- 主比较未产生任何人工接受记录。
- 用户拒绝的数据没有通过原文回退重新进入结果；来源删除、修改后旧内容和不同 agent 数据被排除。
- 同名提及仍有两个不同的 mention ID，没有执行身份合并。
- 在另一条实际代码集成用例中，令 UIE 故意失败，真实本地句式提取器仍保存开放结构；语义仓库持久化和重新打开后可检索。该路径没有创建 V4 Fact 或正式 L1 Claim。这验证的是开放关联库有效，而不是正式事实数量增加。

本次运行使用内存持久化适配器，没有验证磁盘加密。原型返回完整单条消息，没有覆盖跨消息指代、长文本分段/token 预算及实际 LLM 是否遵守来源标记；这些属于后续实现验收。

## 暴露的问题

1. **编号子串误召回。** 查询“样品N1”同时命中 N11 和 N13，反向包含检查也造成查询 N11 命中 N1。4 个多余来源对使新原型准确率降到 88.57%。应对编号采用边界/精确 token 匹配；该问题不能靠增加人工审核解决。
2. **同名扩展噪声。** “同事小陈负责项目M1”和“邻居小陈负责项目M2”保持不同提及，但查询 M1 仍经同名小陈扩展到 M2。在这一个压力查询里，相关 1 条、返回 2 条，准确率为 50%。需降低同名候选权重、结合角色与来源语境重排；必要时只展示原文，不替用户确定对象身份。
3. **跨措辞漏召回。** 原文“编码Z91遇光会变色，需要用黑色包装”，查询“哪种材料需要避光”未命中。没有真实语义检索时，UIE 零结果的内容仍可能漏掉；动态 schema 只能补充已进入候选池的片段，不能保证找回这条原文。

## 实施建议

可以继续按方案开发，无需等待关系注册表穷举完成。优先把来源召回与开放导航接入聊天，并同步处理编号匹配及同名扩展；保留原文、权限和生命周期检查。再接入真实语义模型、动态 schema 与 L2 导航，使用留出真实对话评估。

默认切换前需要检验实际提示词、用户隐私设置、跨会话上下文和 token 预算，并以相同最终预算比较召回/精确率。不能仅根据待确认记录减少验收。
