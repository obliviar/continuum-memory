# 本地开放提取可行性测试（2026-10-01）

## 结论边界

## 样例与指标

`packages/memory/src/eval/local-open-extraction-cases.ts` 包含16条人工设计诊断样例，17条期望关系，覆盖常见关系、陌生科学措辞、状态、评价、多关系、否定、条件、转述、第一人称、显式关系句、Unicode和无关系请求。

使用“关系原文措辞 + 无序参与者文本集合”的严格匹配，评估结构提取而不是入图通过率。此指标不评估角色方向、语境标注和现实真实性，且对合理的不同短语边界较敏感；这些仍需独立评估。它不是业务代表性测试集，不能把样本数值当成生产准确率。

现有 `extractLocalOpenAssertions` 输出10条关系，其中5条匹配；该样本集的结构精确率50%，召回率5/17，约29.4%。所有输出实体/关系跨度均与原文匹配，但跨度正确不等于参与者结构正确。

具体发现：

- 正确处理简单存放、依赖、把字放入、显式“与…的关系是…”和一条Unicode样例。
- “晶体A外延生长于衬底B”“酶E催化底物S的水解”“今天宿舍空调坏了”“deepseek大模型的功能是最强的”未提取关系。
- “小王负责项目A，小李负责项目B”将第二个分句吞入第一个客体。
- “小王把样品交给小李，小李把样品放入冷柜”只产生一条错误组装的放入记录。
- 否定、条件、转述分别将“不”“如果设备修好，”或“小王说”吞入主体短语。

不能据此否定本地句法/语义角色方案；该方案尚未真实运行。结果只说明现有正则不能胜任开放提取主路径，也说明原文跨度校验不足以判断实体边界和配对是否正确。

## 后续：六组 UIE 提取策略实验

按“针对不同情况设计策略”的要求，增加独立实验器 `uie-open-strategy-probe.ts`，在同一16条样例上设计六组对照：

| 策略 | 实验目的 |
| --- | --- |
| domain-baseline | 当前动态领域schema作为对照 |
| flat-general | 分别发现实体、谓词、关系短语、事件触发词、状态词、评价词 |
| predicate-centered | 以关系短语为根，嵌套寻找主体、客体、其他参与者 |
| state-centered | 以状态词、评价词为根，寻找承载对象、评价对象与评价者 |
| clause-predicate | 分句后用谓词中心目标，检查多分句是否改善配对 |
| predicate-followup | 首轮发现关系措辞，再根据模型实际发现的措辞生成参与者问题；最多8个追问目标 |

除对照组外不使用业务谓词白名单，也不从样例答案生成提取目标。完整原文及分句位置保留。逗号切分只作为消融实验：可能切断条件、引语或省略关系，不能直接作为生产策略。

脚本记录每次真实调用的schema、原始响应、耗时和原文窗口。片段覆盖只统计原文精确匹配，不宣称参与者组装准确；`tupleAccuracy` 明确为null，需后续对完整结构独立评估。多轮追问也可能无法区分相同谓词的不同出现位置，属于需要对照验证的限制。

实验器六项单元测试通过，分别验证目标不含业务谓词白名单、分句跨度、追问来自模型片段、无谓词不虚构追问、错误不回退、Unicode跨度。这里用模拟响应验证控制逻辑，**不是UIE质量实验**。再次显式开启真实模型实验，第一条仍以退出码101失败，真实样例完成数0。

复现命令（在packages/memory目录）：


当前尚不能推荐任何一组为胜出策略。需先恢复本地运行环境，取得真实结果，再评估策略组合是否值得接入；没有更改生产提取、审核门槛或L2。

## 用户授权后：真实模型结果（最新）

在仓库`tmp/local-uie-test`下载Python 3.11.15并建立独立venv。旧环境的依赖目录仍完整，因此临时通过PYTHONPATH只读复用这些依赖，未重装整个依赖栈；**解释器独立，但依赖未完全独立**。版本为PaddlePaddle 3.3.0、PaddleNLP 3.0.0b4、NumPy 1.26.4、aistudio-sdk 0.2.6。现有约472MB的UIE-base权重复制到仓库测试目录，动态转静态模型和缓存也在该目录生成，不修改原权重/虚拟环境。实验桥只在测试进程覆盖Paddle硬编码的生成代码缓存目录，未修改生产桥。

本轮六组策略×16条样例完成96组实验、106次模型调用，矩阵耗时约238秒。阳性对照另测官方示例式的体育句子，用具体目标“时间、选手、赛事名称”正确提取出“谷爱凌”、赛事名称和日期，证明运行环境能够正常抽取；不是模型全面返回空值导致的假结论。

| 策略 | 有非空输出的样例/16 | 观察 |
| --- | --- | --- |
| 当前领域schema | 10 | 能找部分实体/属性，但有实体边界与关系标签错误 |
| 通用片段目标 | 4 | 大量空输出，状态/评价角色有混淆 |
| 谓词中心 | 0 | 根目标未识别，无法开展嵌套参与者抽取 |
| 状态/评价中心 | 3 | 有状态词，但未形成目标样例所需的完整参与结构 |
| 分句谓词中心 | 0 | 切分没有解决谓词根目标识别问题 |
| 首轮发现后追问 | 4 | 已返回词触发7次追加调用，主体/客体追问仍未构成可用结构 |

**非空输出不等于正确关系，也不是成功率。**严格谓词片段精确命中统计均为0，但不能将它当作关系召回率：领域schema输出目标对应的对象，且“坏”相对于标注“坏了”存在合理的粒度差异。因此保留原始输出，采用具体实例检查，不报告未经完成的三元组准确率。

实例：

- “晶体A外延生长于衬底B”：这六组均未返回相关结构。
- “今天宿舍空调坏了”：领域目标只返回“今天”；通用/状态目标提取“坏”，却把“空调”作为评价词，未返回状态所属对象；动态追问也未补全。
- “deepseek大模型的功能是最强的”：状态词返回“大”，评价词返回“功能”，未形成目标评价结构。
- “小王负责项目A，小李负责项目B”：领域schema提取了“小李”及“小王”的片段，却输出原文没有表达的“妻子”“父亲”“丈夫”标签。这说明原文中两个名字都存在，不能证明模型赋予它们的关系标签有依据。
- “我喜欢喝牛奶巧克力”：具体“喜欢”目标能提取“喝牛奶巧克力”；上述通用谓词目标没有返回相应关系。

### 结论与下一步

这些结果不支持把本轮抽象schema零样本策略直接用于开放提取主路径，也不能据此断言所有UIE通用目标或微调方案都不可行。可继续尝试更贴合训练分布的目标措辞，或为谓词/论元结构微调；但应增加完整结构标注与未见样例验证。更直接的对照方向是安装本地语义角色/句法模型，利用其谓词-论元输出，再与UIE组合。

同时，全面schema可能制造无依据的关系标签。跨度一致性只证明片段来自原文，不能认证这些标签；即使只用来导航，它们也会引入不相关记忆。该风险已记录，本轮未改生产审核/发布策略。
