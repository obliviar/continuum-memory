# 第六项：图记忆证据可回答性

本轮实现“能否根据当前召回证据回答当前问题”的运行链路，并接入桌面正式图召回。
实际准确率、延迟和拒答率留到统一测评；没有运行真实模型或测试，也没有执行独立阈值校准。

## 三种结果

| 状态 | 含义 | 回答约束 |
| --- | --- | --- |
| `answerable` | 问题所需信息均被判断为有证据，引用与结构检查通过 | 回答限于已记录内容，使用允许的引用，不能推导新关系或声称记忆完整 |
| `needs-clarification` | 身份、意图、时间或冲突存在需要澄清的解释 | 指明歧义并提出具体澄清，不按相似度选一个答案 |
| `insufficient` | 问题存在证据缺口，或判断、预算、有效性检查未完成 | 明确不足；允许归因清楚的局部原文说明，但不能把它当成完整答案，也不能把无命中当成否定事实 |

每个结果保留问题需要的信息项、每项的 `supported/missing/ambiguous`、证据编号、理由代码、覆盖范围。
`calibrated=false` 固定表示当前没有概率校准；没有将余弦值、RRF 或重排分数映射成答案正确率。

## 判断流程

1. 验证证据包、精确引用与遍历解释。空证据、身份歧义或缺少所需关系时直接返回结构判断，不调用模型。
2. 使用当前聊天配置的同一模型，独立读取“用户问题＋已授权证据＋语义和覆盖限制”。
   不发送额外历史，不启用工具，不写入记忆，不修改审核或发布状态。问题、引用和限定字段均作为不可信数据。
3. 模型列出 1–8 个信息需求，并对照人物、事件、属性、时间、否定、说话者、条件及限定信息判断是否补全。
   要求考虑竞争记录；多条兼容事实或原因不自动变成歧义，也不能只挑第一名。
4. 程序校验响应。不存在的引用、非法结构、截断输出、工具调用、失败或超时不能得到可回答结论。
5. 模型等待结束后重新召回，保留原请求的 `knownAt`、可见事实版本和范围，仅更新 recall ID。
   比较精确证据、版本、问题和规划。证据变化或有效性检查失败时撤销原判断，不把旧判断转给新证据。
6. 生成模型收到结构化判断、回答约束和仍有效的证据。每个工具回合重新执行，不跨轮缓存判断。

这是语义模型判断加代码约束，仍可能误判问题需求或语义相关性；不是形式化证明。
最终自然语言回答由提示词约束，不是强制解码或独立的答案逐句校验器。

## 三种证据用途

- `fact`：直接事实需要已知极性、断言模态、无条件、已知有效时间，且未标为冲突或反驳。
  不知道有效时间的记录不能因此证明一个当前状态。
- `statement`：可以说明“来源曾这样说”，保留计划、转述、条件和未知时间；不能改写成已确定的当前事实。
- `relation`：必须引用正式关系及两个端点，并与查询规划的类型、方向、起点匹配。
  仅有目标命题不足以回答原因，路径也不能证明一条未记录的传递关系。

引用的端点存在已返回矛盾边时，不能自动决定哪一方真实。若用户本身询问“哪些记录矛盾”，可以报告该关系。
目前完整性只限召回声明的范围，没有完整记忆盘点或穷尽冲突审计；对全部、唯一、只有、总数等要求
额外完整性的结论保持不足。多个信息项中有一项缺失时，不能用其他项的支持掩盖缺口。

## 接口与预算

- `core/prompt/graph-answerability.ts`：判断接口、默认模型实现、引用校验、三态结果和证据绑定。
- `AgentRuntimeDeps.graphRecall.answerability`：宿主可替换 reviewer、配置超时和输入预算。
- 桌面正式图模式已配置默认 reviewer：最多等待 12 秒，输入至多 16,000 个宿主计数单位；模型输出上限 1,400 token，文本上限 12,000 字符。
- `StreamOptions.signal` 传到现有 OpenAI 兼容适配器，以取消超时请求。其他自定义 provider 应实现取消；
  即使其不响应 signal，迟到响应也不会被采用，但底层计算可能继续。
- 这是一项独立于检索 2 秒预算的判断阶段，可能增加一次模型调用和一次复查召回的延迟及费用。
  只在有待判断证据时调用模型；没有自动更换供应商或安装新模型。
- 最终证据提示词仍接受原图证据 token 上限检查；加上判断结果后超限会弃用本轮证据，而不是不加说明地截断。
- `AgentTurnResult.graphAnswerability` 返回最终状态，宿主可用 `onAssessment` 观察器收集本地结果。
  默认不持久化模型判断、原文或概率，也没有新增桌面结果面板。

未配置 `answerability` 的库调用方不执行语义复核；可恢复的图召回失败仍返回结构化的证据不足或澄清状态。
桌面 `openSourceRecallEnabled` 的原文通道仍是独立模式，
本轮不把它冒充正式 L1/L2 图召回，也不修改输入端提取或自动发布流程。

完整性要求、缺少关系、关系方向不匹配、超时取消、截断响应、判断期间证据变化与原轮次时间保持。
这些用例已运行通过；另增加稳定证据复查后仍可正常注入的对照，避免只验证拒答路径。
真实 BGE 仅验证检索，不替代这里的聊天模型语义判断。由于没有 API Key，真实聊天模型效果尚未验证。
按交付要求，验证后已删除本轮新增的临时回归文件及未使用的 API 测试程序，保留实现与仓库原有测试。
