# L1 实体向量入口与 L2 局部召回（2026-10-01）

本轮按“向量先定位 L1 Entity，再沿图读取”调整桌面图召回入口。Entity 与 Claim 是不同节点；不得把事实向量命中改名为实体命中。

## 当前流程

1. 沿用当前 L1 发布、权限、保留许可、时间与来源验证，得到可读视图。
2. 使用独立 Entity 向量缓存检索实体，向量文本为规范名称、别名和实体类型；缓存键包含作用域、精确实体版本及来源，文本另有内容哈希校验。
3. 实体阶段按向量排名选择最多 4 个候选，且受请求 maxSeeds/maxNodes 上限约束。这个 Top-K 是导航候选，不是实体身份合并或答案置信度。
4. 通过精确实体引用的邻接索引，找到当前可读的相邻 Claim；不会把没有实体引用的旧标量记忆自动补造为 Entity。已知实体名称约束继续检查。
5. 如果查询就是某个已选实体的完整名称/别名，返回该实体的合格关联命题。其他问题仅在这些相邻命题内做局部事实向量选择，仍使用原有暂定 0.8 阈值；没有全局 Claim 回退。相同模型与问题的向量在两个阶段共用。
6. L1 直接问题返回命题及来源；L2 关系问题从选择的 Claim 出发，按已有关系类型、方向和预算进行局部广度优先遍历。L2 边端点仍是精确版本 Claim，不修改权威图结构。
7. 来源、权限和版本变更检查继续生效。缺模型或所需向量不可用时不会暗中切换成关键词检索；部分缓存会记录不完整状态。

## 索引与性能边界

- L1 Entity→Claim 索引按发布版本缓存，缓存最多保留 4 个视图，只存引用键。每次查询仍将索引结果与当前合格 Claim 集合相交。
- L2 每个固定读取视图一次构建邻接索引，邻居分页不再反复投影、筛选整批关系；精确关系读取也复用引用表。重复的同节点分页复用已筛选结果，来源授权仍逐次检查。
- L2 增加轻量 manifest 读取，避免每页为检查版本复制全部关系。持久化适配器的读取成本未改变。
- 当前 Entity 与局部 Claim 向量使用 **exact-flat 精确索引**，不是 HNSW/ANN。实体向量比较仍是 O(E×d)；局部命题向量比较是 O(C_local×d)。trace 记录索引类型和实际向量评分数量。
- 初始化索引、固定视图准备、现有来源与权限核验仍可能全量处理记录。不能把本轮描述成“整个请求完全没有线性扫描”或承诺整体亚线性复杂度。
- 没有新增边语义重排、规则证明、自动关系采纳或答案概率校准。

## 桌面接入和对照

桌面图模式默认使用 `entity-vector`。库调用方未指定 `retrievalMode` 时仍使用 `hybrid`，保持已有集成兼容。启动进程的 `CONTINUUM_GRAPH_RETRIEVAL` 可选择：

| 值 | 含义 |
| --- | --- |
| `entity-vector` / 未设置 | 实体向量入口 → 局部命题 → 按需 L2 |
| `vector` | 旧事实向量直接选 Claim 的对照，不是 Entity 入口 |
| `hybrid` | 保留关键词、向量及已有结构化策略的对照 |
| `lexical` | 无向量的对照；L2 保留原有精确命题/实体定位规则 |

在聊天前的 L1/L2 同步屏障中，用已启用的本地模型准备实体向量。独立缓存只在内存中，不写入事实向量缓存，不下载模型。每次准备最多新增 128 个向量，后续屏障继续处理剩余项；应用重新初始化后重新准备。旧模型/旧实体版本/旧文本不能命中新记录。

## 验证与限制

- `entity-vector-regression.ts`：23 项合成向量测试验证 L1 与 L2 接线、查询向量复用、权限/删除/版本、缓存撤销、精确邻接及预算。这不是模型质量测评。
- 集成入口 `run-direct-recall.mjs` 已纳入新回归。
- `run-entity-vector-model.mjs`：本地真实模型比较四种入口，同一固定原生图、问题、预期证据和预算；不读取用户数据库，不下载模型。

```powershell
node packages/memory/src/graph-core/eval/run-entity-vector-model.mjs --model-dir '<已安装模型目录>' --report '<报告路径.json>'
```

本轮小样本诊断使用 2 条同义工作经历 Claim、2 个 Entity、9 个问题。按完整预期证据集合严格匹配：关键词 4/9、混合 4/9、事实向量 3/9、实体入口 5/9。这个结果仅用于发现问题，不能称为整体问答准确率或通用质量提升。

实体入口仍漏掉三个职业改写问法，且“Bob works at Acme”存在错误人物匹配：当前已知名称约束不能识别所有陌生人名。接下来应扩展跨主题人工确认测试集、完善实体目标约束和局部候选重排，再评估阈值与近似索引。不可只凭本次 9 例调阈值。

本轮验证：集成 312 项检查及原始直接召回 12/12 通过；memory TypeScript 检查通过。桌面主进程采用 `--composite false --incremental false --rootDir .` 的跨包源码检查通过；原桌面 tsconfig 单独检查仍存在跨包测试引用的 rootDir/include 限制，本轮未修改该配置。未启动 Electron 读取用户记忆，未提交代码。
