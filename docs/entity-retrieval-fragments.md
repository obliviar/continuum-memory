# 实体多片段检索入口（2026-10-03）

本轮只调整召回侧派生索引，不改变输入端权威 Entity、Fact、Claim、L2 关系或用户数据库。
基于当前本地代码实现，尚未对接输入端新增的基础关系发布、后台 API 复核和下一轮可见性接口。

## 数据流

```text
已发布、允许检索的 L1 + 精确 V4 Fact + 当前来源
  → collectCurrentL1 与来源/权限校验
  → Entity 名称片段 + 关联 Claim 的事实文本片段
  → 本地实体向量缓存

问题 → 检查当前权限、时间、版本与来源
  → 只比较合格片段的向量
  → 按精确 Entity 引用聚合，最大片段相似度排序
  → 实体 Top-K → 实体邻接 Claim → 原有局部事实排序与证据筛选
  → 直接事实证据，或作为 L2 受限遍历起点
```

实体第一阶段不再只依赖名称、别名、类型；相连事实的内容也可定位实体。多个片段命中同一
实体时只占一个实体候选位置，不按命中次数累计加分。片段多的实体仍可能存在统计优势，
目前以固定数量上限限制，并未证明排名无偏或召回质量提高。

## 投影约定

- `projection/entity-retrieval-projection.ts` 生成可重建的检索文档，策略版本为 `entity-claim-fragments-v1`。
- 名称文档保留旧 ID 与内容，支持旧名称对照；事实片段使用独立 ID 空间。
- 每个事实片段绑定精确 Entity、Claim、Fact 引用，以及 Claim 和 Entity 的来源。
- 片段 ID 包含实体、命题、标准化事实文本和策略指纹。身份、版本、来源或权限变化后不能误用旧片段。
- 仅从明确的 `claim.atom.args` 实体引用建立关联，不从正文猜测身份，不处理开放提及或自动合并同名实体。
- 使用原有 `fact.canonicalText`，不调用模型生成摘要，不新增主题别名或事实。
- 一个片段最多取 384 个 UTF-16 单元的事实文本，实体前缀最多 256 个；切片避免拆开代理对。
- 每条 Claim 最多 4 个事实片段，每个 Entity 最多 32 个事实片段，另有 1 个名称文档。
  优先给不同 Claim 首片段，再加入长 Claim 的后续片段；Claim 按记录时间从新到旧排列，引用用于稳定排序。
- `textSpan` 只定位标准化 Fact 文本，不冒充原始聊天证据跨度；原文引用仍通过正式 Claim 来源回读。
- 超过长度或数量上限会记录 `entity-truncated-claims`、`entity-omitted-fragments` 并标记检索不完整。

## 权限、缓存与预算

`prepareV4EntityVectors` 复用当前正式 L1 收集接口，检查检索许可、精确事实和来源。
桌面准备阶段沿用聊天分享策略，禁止内容不会因需要建立片段而被放宽权限。
低层 `prepareEntityVectors` 仍可用于对照，但调用者必须传入已校验的 entries。

准备和查询调用相同文本投影函数；查询只使用本次合格 Claim 构建的文档。
查询过滤后有可能出现准备阶段数量上限之外的片段；没有对应向量时明确记录缓存不完整，
不会临时把全库事实接入，也不会自动切换成关键词模式。

缓存是本地进程内派生数据，使用模型指纹和精确文本匹配。下一次准备会移除不再属于投影的
缓存 ID；异步准备期间发布版本或访问策略改变则拒绝写入并清除本次投影对应缓存。
删除到下一次准备之间可能仍有旧向量驻留，但查询不会把不再合格的旧文档加入比较集合。
来源删除后的安全性不依赖等待缓存物理清理。

每次准备最多计算 128 个缺失文档向量，继续沿用现有批量限制；它不等于时间预算。
查询的实体 Top-K、最终 Claim 数、L2 遍历预算和证据预算仍分别控制。
事实片段相似度只参与实体导航，不替代最终事实向量分数，不代表答案正确概率。
片段截断导致否定/条件上下文不完整时，最终证据仍回读完整事实及其语义标记。

本轮仍使用精确向量比较。投影构建、有效性过滤及向量比较需要扫描相应集合，未引入 ANN，
也未宣称检索耗时降低。

## 开关与诊断

- 桌面实验图仍需 `CONTINUUM_GRAPH_MEMORY=1` 和可用本地语义模型。
- 桌面实体入口默认使用 `claim-fragments`；`CONTINUUM_GRAPH_ENTITY_TEXT=name-only` 保留名称对照。
- 库级 `entityRetrievalTextMode` 默认保持 `name-only`，宿主可显式传入 `claim-fragments`；准备阶段须使用相同模式。
- 关键词、hybrid、事实向量模式不使用实体片段入口。
- trace 新增文本模式、文档数、截断数、聚合方式，以及选中实体最多 4 个命中文档/Claim 引用。
  这些引用用于诊断，不作为额外事实注入。

## 后续输入端对接

1. 从 ready 投影读取正式发布结果，保留原始参与者的精确实体角色及 Claim/Fact 版本。
2. 明确输入端允许检索的状态与当前 `review.retrieval.retain` 的映射，不能直接把开放断言当成正式 Claim。
3. 对接轮次开始时的可见快照：本轮检索和向量准备使用同一可见版本，新发布内容不提前进入本轮回答。
   本轮没有改变原有捕获刷新和发布时序，因此还不能宣称已满足新的下一轮可见性约定。
4. 后台同义/反向映射、澄清和撤回若改变语义，需发布新版本并使旧片段及相关 L2 视图失效。
5. 基础关系谓词可产生正式 Claim，但不能据此自动生成 `causes` 等命题间 L2 关系。

## 第二轮：实体候选选择与局部事实衔接

将已知名称/别名目标检查前移到实体向量比较和 Top-K 之前：只有绑定了问题要求的已知实体的
合格 Claim 才能贡献片段，拥有这些 Claim 的实体才进入导航。仍沿用现有保守实体约束，
不是通用指代消解；不能识别任意陌生人名，也不推断主客体角色。同名不同身份保持独立及歧义标签。

`recall/entity-candidate-selection.ts` 独立处理实体聚合、候选池与可替换实体重排：

- 库宿主通过 `entityCandidateSelection` 配置，和最终 Claim 的 `candidateSelection` 分开。
- 实体候选池默认最多 16 个（当最终实体数大于 16 时相应扩大），宿主可在 1–256 内配置，
  但不能小于最终实体数。桌面最终实体数仍通常为 4，并受已有请求预算约束。
- 先按片段最大相似度聚合精确实体引用，再保留实体候选池；同一实体不会重复占位。
- 可选实体重排器最多读取该实体 4 个最高分命中文档的合并文本，最多 2048 个 UTF-16 单元；
  只能重排候选池已有 ID，不能引入身份或直接通过证据准入。无效输出/失败/超时保留原导航顺序并记录状态。
- 本轮只接好可替换接口，桌面没有默认启用新的实体重排模型，不能宣称已获得模型重排收益。
- 未选中的实体和被截断的候选池如实记录；这些限制及片段截断通过固定标签进入 Agent 的限制说明。

命中的片段 Claim 线索继续传递到局部事实阶段，但仅在完整事实向量分数完全相同时优先排序。
不把片段分数与事实分数相加，不改变 0.8 等已有准入门槛，不直接增加事实分数。L2 向量种子
排序保留该同分顺序，仍执行身份和目标状态检查。多个 Claim 共享同一 Fact 时仍保留精确 Claim 身份。

这些修改继续遵守“不运行测试”的安排；仅做静态类型与差异检查。优先检查和实体 Top-K 的
交互、同名歧义、重排失败回退、局部候选截断等行为仍需后续运行验证。

## 本轮验证范围

按要求没有运行测试、模型对照、桌面交互或用户数据迁移。仅进行 TypeScript 静态检查和差异检查。
后续需验证不含实体名、同名实体、多主题、片段上限、权限撤回、来源删除，以及发布期间快照变化。
