# 未知关系正式发布到 L1

## 本轮实现

桌面提取入口现在会在保存原始 extraction 后建立独立的发布视图：符合条件的开放 assertions 和未注册 facts 进入基础关系注册、来源局部身份处理及现有 V4 → L1 → ready 投影发布链路。它们成为正式 Claim，不只是开放导航记录。原始模型输出、assertions 和原文保持不变。

基础注册表保存于宿主提供的加密 `graph-basic-relations.enc`。关系 ID 由 owner/agent/session、原文关系措辞、角色及观察类型确定。相同签名复用 ID，输出参与者顺序变化不重复注册；不同角色或观察类型暂时保留独立定义。本轮不做 API 同义合并或跨来源实体合并。

## 自动发布条件

- 提取完整、来源 hash 和证据跨度有效，所有参与者可对齐到原文。
- 未知关系措辞直接出现在原文，关系跨度不与参与者名称重叠。
- 开放 assertion 至少有一个明确角色；支持单参与者事件和多个参与者的关系。
- `unknown` 角色、未解析的局部代词、缺失关系跨度或损坏输出继续保留为开放候选。
- 未注册的二元 fact 也支持有原文依据的字面值对象。
- 低分、未知时间、否定、条件和转述不独立阻断发布，但语境必须保留，不成为当前肯定事实。
- 私密来源沿用现有分享策略；secret 来源不会通过桌面入口自动创建基础关系。用户拒绝不能被策略重放覆盖。

基础定义记录原文表达、角色与观察类型，标为 `registrationKind: basic`；不声称已完成领域含义规范化，不启用唯一性、对称性或传递性。不同来源同名对象默认创建独立的来源局部实体。

## 持久化与读取

V4 Fact 和 FactVersion 新增可选 `sourceStatement`，保存关系 ID/版本、原文措辞和跨度、完整角色参数。原有 subject/object 字段作为兼容的存储锚点；多参与者陈述的所有参数以 `sourceStatement` 和正式 Claim 为准，不把两个锚点变成独立的二元业务事实。

L1 读视图将 Claim 的全部参数、关系表达与对应 V4 精确版本核对，第三个及更多参数被篡改也会失效。基础关系不生成旧的实体间便利边，Claim → 各参与者的角色投影仍完整建立。正式图召回返回原文及 Claim 引用。

沿用持久化 publication outbox：注册定义先可用，Fact 写入后再发布 Claim、语义 bundle 与 ready 投影。写入失败可重试，重复执行同一 extraction 不重复发布。没有完整投影的记录不进入正式图召回。重启加载动态注册表后可重建发布视图。

V4 生命周期保留 sourceStatement 版本，人工正文改写取消旧的来源结构；彻底删除时同步清除 Fact 与历史版本中的结构化内容。清空记忆也清空基础注册表。

## 使用与边界

开发环境更新后需要重新启动桌面进程。在开放关系优先或智能提取模式下，新的合格提取结果会自动进入本链路。查看记忆管理中的已发布 Claim 数量；正式图召回仍遵守已有启用条件与发送权限。

本轮实现新提取结果的正式 L1 发布和重启恢复。未自动全量迁移历史开放记录；历史记录可通过重新提取产生新结果。来源局部身份、基础角色定义不能替代语义正确性评测，原文对齐不是现实真值认证。

后续的 API 关系复核、同义映射、澄清交互、非阻塞提取和 L2 适配现已接入，详见 [后台工作流说明](l1-background-semantic-workflow.md)。注册操作仍不解除 L2 的端点、身份、上下文和时间检查。

## 验证

新增集成测试覆盖：开放 API → 正式 Fact/Claim/投影 → 正式图召回、三参与者保留与参数篡改、重启与幂等、歧义候选保留、不同角色及身份隔离、否定/条件语境、用户拒绝、发布失败恢复、彻底删除和实际开放提取器接入（模拟 API 响应）。测试不代表真实 API 模型的提取质量。
