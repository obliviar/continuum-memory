# 桌面 Skill 模块

## 入口与调用

桌面顶部“Skill”与输入区“管理 Skill”打开管理面板。输入区可以选择本轮工作流，也可以保持“按任务自动选择”。选择对话时恢复该对话的 Skill 选择；加载记录只展示当前对话。

内置七个工作流：网络研究、本地文本文件分析、结构化信息提取、摘要与行动项、方案比较、翻译与改写、记忆证据核对。网络/文件工作流使用已有 `web_search`、`http_fetch` 和 `file_read`；其他工作流通过聊天模型处理用户提供的文本。

另提供 `PDF 文档` 与 `Word 文档` 两个桌面适配工作流，运行时探测通过后可启用。读取、生成、预览与部署依赖见 [desktop-documents.md](desktop-documents.md)。本机原始 PDF/Word Skill 需要完整 Codex 能力时仍保留依赖提示，并提供“使用桌面适配版”按钮。

模型可调用 `list_skills` 查找已启用的工作流，再用 `use_skill` 加载指导，使用 `read_skill_resource` 获取本机 Skill 的相对文本引用。界面手动选择则由主进程加载同一份指导，作为本轮临时工具上下文传给模型。

## 本机 Skill

默认扫描 `$CODEX_HOME/skills` 和 Codex 缓存中的 bundled、curated、curated-remote、primary-runtime 插件目录，也可从界面添加目录。识别带 `name`、`description` 元数据的 `SKILL.md`，支持折叠说明与 `required-tools` 数组/多行列表。缓存中同来源同名 Skill 使用较新的路径版本。

本机 Skill 默认关闭。文本与现有工具兼容的项目可手动启用；依赖专用连接器、桌面控制、生图、文件生成或脚本执行的项目列入清单并显示缺失能力。依赖识别是保守的兼容性检查，不是对任意第三方工作流的完整能力证明。

例如：

```yaml
---
name: text-review
description: 阅读用户指定的文本并核对事实表达。
required-tools: [file_read]
---
仅依据提供的文件说明结论，未知信息明确标注。
```

“查看工作流”只显示内容；启用和加载均不会执行脚本或安装软件。支持的引用资源限制在该 Skill 包内，并验证真实路径、类型与大小。

## 状态与数据边界

- 启用状态与添加的目录保存在系统保护的 `skills-state.enc`。
- 本机文件改变后，旧启用状态失效，需要重新扫描并核对后启用。
- 工作流按需发送给当前聊天 API，不会每轮附带全部 Skill 文件。手动加载不会改写用户原话，也不作为 L1 提取证据。
- Skill 指导只保留在当前模型调用的临时工具上下文，不写进聊天历史或长期记忆。Skill 加载不构成读取无关文件、向外发送数据或发布事实的额外授权。
- 加载记录保留最近 50 项，仅含名称、版本、时间与触发方式，按对话隔离，应用退出后清空。
- 此模块提供工作流发现和指导调用，不会把 Codex/ChatGPT 的工具或插件账号自动接入桌面助手。缺少执行依赖的模块暂不可启用，需要对应适配器后才能实际执行。

## 验证

单元测试覆盖内置工作流、搜索与加载、默认禁用、启用持久化、文件更新、缺失依赖、资源越界和存储失败。运行时测试确认手动 Skill 不进入用户证据或下轮历史。

真实 Electron 测试使用合成 SKILL.md 和本机模拟 API，覆盖管理面板、依赖禁用、本机启用/重启、手动选择、模型函数调用、对话记录隔离，并复测对话分区与输入交互。

本次环境扫描得到 53 个本机 Skill；其现有工作流均需要当前桌面端尚未接入的专用执行能力，已全部展示为不可启用。当前七个内置工作流可用；兼容纯文本的本机 Skill 在合成样例中验证了发现、启用、加载与重启恢复。

全量回归 962 项通过、17 项跳过；随后增加的三项专用依赖检查也通过，Skill 专项共 9 项通过。桌面端与核心类型检查、生产构建以及真实 Electron 模拟服务测试通过。
