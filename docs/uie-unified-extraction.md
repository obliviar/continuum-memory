# 统一 UIE 提取入口

桌面、CLI、HTTP server 和 MCP 使用 `@continuum-memory/memory` 的同一套本地
UIE-base 模型桥接及结果转换。模型成功时保留规则提取的既有记忆候选，并附加
UIE 候选；模型不可用、超时、输出异常或图记录失败时仅返回规则候选。模型分数
本身不构成自动通过依据：只有分数至少 0.85、主客体与关系词在同一原文陈述中，
且没有否定、问句、假设、转述、引号或相对时间的受支持低风险关系，才标记为
`requiresReview: false` 并进入现有写入校验。其余候选仍待人工审核。

图事实对普通 UIE 嵌套关系采用独立门槛 0.80。经局部分句绑定为明确“我 + 关系词 +
UIE 对象跨度”的第一人称关系采用 0.70 门槛（本机 UIE 对直述偏好的实测分数约 0.707）；
两者仍须通过原文关系词、谓词注册与实体类型核对。明确的第一人称“喜欢”、修读课程、上课地点及参与项目
可按同一规则自动评估；普通长期记忆的 0.85 门槛没有降低。否定、问句、假设、转述、
引号、相对时间、未知谓词和类型不符仍待审。

## 日常对话进入图审核

共享 schema 增加 `课程`、`上课地点`、`爱好`、`喜欢`。除了模型直接输出的嵌套关系，
适配器也可以把 UIE 字段转换为有来源的关系候选：仅在同一分句存在明确的“我”以及
对应关系表达时绑定主语，例如“我每周三都要上电磁学和复变函数”产生两条 `修读课程`
候选，“我一般在西区三号教学楼上课”产生 `上课地点`，“其实我很喜欢打乒乓球”产生
`喜欢`。姓名、职业、居住地、当前项目也须有明确的局部表达才转换。

对象必须来自 UIE 的有效原文跨度，不能由规则补造。只有实体、字段误分类、他人陈述、
引号中的“我”以及无法绑定的字段不会被硬凑成用户关系。字段转换记录
`adapterVersion: uie-personal-relations-v1`，保留未修改的 `uieRawOutput`；主体“我”仍是
待确认提及，不会仅凭“我”自动绑定到用户身份。上述明确陈述可自动解析否定、条件与
说话者，并用完整分句作证据；其他语境仍需审核。自动图身份只创建按来源、版本和提及
隔离的 `source-entity`，同名人物或组织不会跨来源合并。模型低分仍可进入待审核列表。

`每周三` 等周期时间目前保留在证据中；现有时间审核只接受日期、`none` 或 `unknown`。
对于周期或相对时间，应选择 `unknown` 保留不确定性，不能把它标成某个单日或无时间约束。
本次没有扩展周期时间协议，也没有把“今晚要做实验”的计划自动当作已发生事实。

待审核记录现在独立于 L1 发布资格保存。桌面启动时从仍保留的提取记录恢复遗漏的审核项，
恢复操作不调用模型、不发布 Claim，不覆盖已审核的决定。原本没有候选的旧记录需要重新
运行模型：在记忆管理中使用“重新提取无事实记录”，每次最多处理 5 条来源，保留历史
提取结果。任何已产生事实候选的同版本来源都不会通过该入口重复提取；提取期间若来源
被删除或存储重新初始化，则停止保存。新界面分别显示提取次数、事实候选数、待审数和
Claim 数，并显示每条候选的主语、谓词、对象和原文。

记忆管理中可手动触发“按新策略自动重审图事实”。每次最多审核 20 条策略待审项，
仅对仍然有效且原文完全一致的来源，使用保留的原始 UIE 输出重新计算派生语境；
不会重跑模型、改写原始提取，也不会覆盖用户确认、拒绝或继续待审的决定。
只有通过当前审核并成功提交 V4 Fact 与 L1 Claim 的候选才计入已发布。

开发环境更新后需重启桌面进程，让本地 UIE 工作进程加载新 schema；打包版需重新构建。

验证：`packages/memory/src/long-term/uie-auto-review.test.ts` 覆盖明确陈述自动通过、
疑问/假设/转述/否定/时间阻断和来源隔离；`graph-policy-reassessment.test.ts` 覆盖
旧候选安全重审与人工决定保护；`uie-graph-review.test.ts` 覆盖待审持久化、重启恢复、
人工确认后的稳定 L1 视图、误归属防护和原文不变性。设置下述 Python 和模型路径环境变量
后，同一测试还会运行已安装的 UIE-base，验证课程、教学楼、乒乓球和父亲关系四类实际输入。

## 配置

CLI、server、MCP 读取以下环境变量；桌面仍可从 `config.json` 配置同名模型路径。

- `CONTINUUM_MEMORY_UIE_PYTHON`：Python 虚拟环境中 `python.exe` 的绝对路径。
- `CONTINUUM_MEMORY_UIE_MODEL_PATH`：直接指向包含 `model_state.pdparams` 的
  UIE-base Taskflow checkpoint 目录；或使用 `CONTINUUM_MEMORY_UIE_MODEL_HOME`
  指向包含 `taskflow/information_extraction/uie-base` 的模型根目录。
- `CONTINUUM_MEMORY_UIE_SCRIPT_PATH`：仅在自定义部署布局时覆盖共享 Python 桥接脚本路径。

Windows 开发机在没有显式配置时沿用 `D:\Models\UIE-mini` 的既有默认位置；
其他环境找不到模型时自动使用规则提取。Python 桥接在同一进程内复用已加载的
Taskflow，并顺序处理请求；空闲五分钟后释放。冷启动仍可能较慢，不能据此保证
聊天或批量写入的低延迟。

## 各入口边界

- 桌面：自动捕获在所有提取模式下尝试 UIE。规则候选照常参与原有记忆写入；
  UIE 图结果按图提取开关进入现有加密记录、身份确认和 L1 审核流程。
  `uie` 模式仍强制保存图候选；`smart` 模式保留额外的聊天模型提取。
- CLI/server：自动捕获运行 UIE + 规则组合，但目前只有 V3 存储。符合上述条件的
  UIE 普通候选可经现有校验自动写入；尚无可发布的 L1 图审核仓库，不能把“已调用 UIE”等同于“已入图”。
- MCP：`remember` 仍只保存用户明确提交的原句。UIE 提取结果作为未审核建议返回，
  不写入图；失败时仍保存原句并报告规则模式。

进一步统一 L1 发布需要为 CLI/server/MCP 分别接入有作用域隔离的原文捕获、
加密图提取存储、身份与审核入口；本次图自动发布仅接入桌面端。
