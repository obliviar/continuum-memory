# L2 问题与关系规划（2026-10-03）

本轮继续原计划第 4 步：在边排序之前明确哪些关系可以走，以及方向是什么。
只扩展召回查询规划，不新增关系类型、不写入图、不改变关系采纳机制，暂未对接输入端新接口。

## 支持的方向

以下是有限语法的代表性形式，不代表任意自然语言表达都能识别。

| 问法示例 | 问题类型 | 关系类型 | 相对于目标命题的方向 |
| --- | --- | --- | --- |
| 为什么比赛取消 | cause | causes | in：找原因 |
| 暴雨导致了什么 | effect | causes | out：找后果 |
| 比赛取消之前发生了什么 | before | precedes | in：找较早事件 |
| 比赛取消之后发生了什么 | after | precedes | out：找较晚事件 |
| 什么能解释比赛取消 / 比赛取消的依据是什么 | explanation | explains | in：找解释依据 |
| 场地无法使用能解释什么 | explained | explains | out：找被解释命题 |
| 什么蕴含设备无法启动 | premise | entails | in：找已记录的蕴含前提 |
| 设备断电蕴含什么 | implication | entails | out：找已记录的被蕴含命题 |
| 哪些说法与比赛取消矛盾 | conflict | contradicts | both：找已记录的冲突 |
| 比赛取消相关的记忆 | related | 五类正式关系 | both：有限泛关联查询 |

新问法提供相应的有限英文形式，如 `what explains X`、`what does X explain`、
`what entails X`、`what does X entail`、`what contradicts X`。
提取的目标文本用于找候选 Claim，并不证明该目标事件发生过。

解释、因果、蕴含、先后保持独立：解释依据不自动等于原因，先发生不自动等于导致，
返回蕴含边不等于执行推理证明。`contradicts` 只读取已记录冲突，不判断哪条事实为真，
也不自动判定新旧替代。没有矛盾边不代表已经排除了所有冲突。

## 歧义与分流

- 识别到多个问题类型时返回 `competing-intents`，不自动取所有关系类型的并集。
- 多个分句分别提出关系问题时返回 `multiple-targets`，首版不自动拆解成多次检索。
- 新问法缺少明确目标时返回 `target-event`；“这件事”“这个结论”等未解析指代需要澄清。
- 两个指定事件“哪个在先”的比较问题暂未实现双目标解析，不把它误当作单目标前向/后向查询。
- 仅说“解释一下”或泛泛“支持什么”不自动映射成因果/蕴含；受识别范围限制的关系问句进入澄清分支。
- 共享 `hasGraphRelationIntent` 用于桌面宿主分流和直接 L1 路径的保护，避免关系问题落入普通事实检索后
  用若干无关系的事实拼接答案。该识别器仍是有限启发式，未解决所有实体名称与问题词的歧义。
- 宿主给出精确目标、问题类型或自定义方向/类型时，继续保留可信调用方配置，但必须符合正式 L2 关系名称。
  旧样例的 `causal`、`contributes-to`、`before` 不会自动转换成正式关系。

## 时间、跳数与证据

沿用现有日历时间规划器，`knownAt` 不被问题中的日期改写；相对时间需宿主提供参考时间和时区偏移。
未知、模糊或不支持的时间表达仍明确报错。含日期并带“之前/之后”的复合问题没有自动放宽时间范围，
目前可能要求显式规划；目标时间与邻居时间的独立规划留待后续实现。

跳数继续服从请求预算和宿主上限，桌面 L2 上限仍为 2。不同问题类型不会自行扩大跳数，
本轮没有实现从“查三跳”等自然语言修改预算。所有节点、边与来源沿用固定版本、权限及语境检查。

trace 增加 `missing-information` 和 `relation-kinds`，与已有 `question`、`direction` 一起记录规划。
Agent 提示明确各关系的方向和含义，多条解释可以并存，不能按相似度宣布唯一解释。
返回 `needs-clarification` 的规划由现有适配器以 `unsupported-capability` 和具体原因传递；
本轮未新增桌面澄清 UI，也未改变公共错误协议。
