# Entity identity and predicate normalization

The UIE extraction store keeps source spans and mention text. `graph-normalization.enc` separately keeps the entity catalog, reviewed alias decisions, mention-to-identity resolutions, and normalized fact candidates. Both stores use OS-protected keys. Source truncation removes the corresponding extraction and normalization results; clearing memory clears both stores.

Identity resolution accepts a trusted explicit Entity ID first. It can then use an established unique alias or a unique name candidate already anchored in the authorized conversation context. A canonical-name match alone remains unresolved. Vector similarity produces ranked candidates only. Type and scope must match; invalid explicit IDs fail closed. Only accepted alias decisions affect canonical IDs, and a later split revokes an earlier merge.

The predicate registry defines directed roles and expected types. The initial entries are `worksAt(person, organization)`, `headquartersIn(organization, location)`, `bornOn(person, date)`, and `salaryAmount(person, amount)`. Natural-language labels have explicit forward or reverse mappings, so `employs` fills the same roles as reversed `worksAt`. Unregistered or type-incompatible labels stay unresolved. Dates remain date literals and monetary values remain numbers with currency units; no entity is created from a literal.

The current `experiment` branch does not contain the graph-core package where `GraphEntityRecord`, `GraphAliasDecision`, and `GraphPredicateSpec` are defined; those definitions are visible on `origin/feat/graph-core`. This module accepts structural views compatible with those records without merging that entire branch. The catalog is empty until a trusted graph-core publisher supplies records through `replaceCatalog`; therefore current app captures unresolved identities instead of guessing from names. Normalized results are candidates for a future graph writer, not accepted graph facts.
