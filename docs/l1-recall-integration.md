# 2026-10-01 入口调整

桌面图召回现在默认以 L1 Entity 向量作为入口，再通过精确实体引用寻找局部 Claim，按需进入 L2。库调用默认仍保留 hybrid 兼容模式。实现、对照开关和性能边界见 [实体向量与局部召回](./entity-vector-local-recall.md)。下文原有混合入口说明仍适用于对照模式。

# 实体 L1 与固定视图召回接入

本轮将 `xunmiao1031/feat/graph-core` 的直接事实召回接到当前 L1 写入结构。
`graph-l1-projection.enc` 与 `graph-relations.enc` 分别是本地已审核 L1/L2 的权威视图；
`memory-graph-l1.enc` 只是从当前 V4 与原生 L1 重新验证得到的直接召回读缓存，不是第二个写入权威。
普通聊天仍默认使用既有 V3/V4 召回；`CONTINUUM_GRAPH_MEMORY=1` 显式启用实验图召回，
直接问题走 L1，受支持的关系问题读取已审核的 L2。

## 当前数据流程

```text
原文捕获 → 实体/命题提取 → 现有身份与语义审核 → 发布 V4 精确版本
  → 原生 L1 Claim / 语义集合 / ready 投影
  → 检索许可筛选 → collectCurrentL1 合并读取投影
  → 原文关键词 + 实体名称/别名 + 可用向量缓存
  → 固定视图回读 Claim / Fact / Source → 带引用的回答证据
  ↘ 已审核 L2 关系 + 有界遍历 → 关系证据与路径说明
```

审核流程仍沿用上游实现；本轮没有为最终的 L1 审核政策定案。`candidate`、`pending`、
未发布任务不直接成为回答依据。检索保留与主动偏好使用是两项独立许可。

## 本轮接口与行为

- `adapters/accepted-l1-input.ts`：统一收集旧标量和原生实体 Claim。原生 Claim 保留原来的
  ID、版本和上下文，不重新生成标量身份。检查当前 V4 版本、原文哈希、支持链接、UTF-16
  范围、权限和时间。原生投影过期时不读取缓存中的旧 Claim。
- `V4GraphMemoryOptions.acceptedBundle`：受信宿主提供当前 ready、且允许检索的语义集合。
  每次读取都会重查；同一份输入用于候选检索和固定视图，避免两个接口使用不同版本。
- `selectRetrievableGraphBundle`：保留已发布且允许检索的 Claim；带 `graphTaskId` 的原生
  V4 事实不能通过标量回退绕过这一限制。
- `GraphReadView.resolveEntities?`：可选精确实体读取接口，以 ID 和版本读取，同名不会自动
  合并身份；需要至少一个当前允许读取的关联 Claim，并消耗共享节点与证据预算。
- 实体规范名称与已有别名进入候选文本；相似度或名称匹配只用于找到 Claim，不产生关系。
- 未知时间只在未指定日期、使用默认当前时间的直接检索中作为原文材料返回，并标记
  `incomplete`。指定日期/历史区间和 L2 默认读取仍排除未知时间。否定、条件和不确定语义
  保留原样，不转换为当前肯定事实。
- 原文读取仅接受该 Claim 已记录的精确来源定位，调用者不能将片段擅自扩大为整段原文。
- `includeOwnedSessions` 由宿主显式授权；普通 L1 owner 级查询可覆盖旧会话，明确 session
  查询及不同 owner 仍隔离。它不自动授予跨会话关系发布权限。
- 实验性 Agent 图召回在读取前等待捕获写入、刷新 V4 待写队列，再同步原生 L1 投影。
  `graph-l1-recall-barrier.ts` 在异步等待前后检查宿主是否重新加载；更新失败时不继续回答。

## 原生 L2 接入（2026-09-29）

实体 Claim 经 `prepareRelations` 保持精确引用；撤回检索许可会使旧视图失效。
桌面聊天的 L2 入口通过 `V4L2MemoryOptions.nativeRelations` 读取现有审核仓库
`graph-relations.enc`；关系复核仍由桌面现有审核入口执行。只有显式采纳、且满足检索许可、
时间、来源和访问策略的关系才能进入图问答证据包。隔离的旧标量 L2 路径保留用于兼容和
回归；桌面不创建第二份 `memory-graph-l2.enc`，原生仓库不可用时也不回退到旧关系库。

`native-l1-read-adapter.ts` 保留原生 L1 manifest 和精确 Claim 引用，将实际读取委托给
允许检索的合并 L1 固定视图。两份视图必须同时有效；不修改已存关系的端点或版本。
源文仍从当前 V4 回读。撤回许可、修改/删除来源、投影变化或仓库重载都会拦截旧读取；
复核报告不展示不允许检索的端点文本，已有预览凭据在重载后也失效。

桌面读取前在等待写入、同步 L1 后，等待上游 L2 串行同步队列。该队列沿用原有
`rebaseGraphRelations` 检查精确端点、清除失效记录，并暂存待审核候选与模型观察；
不会采纳新关系。读取层本身不发布或改绑关系。

关系查询的候选文本包含有权限的实体名称/别名，并增加查询目标与名称/别名的精确匹配
入口，与关键词、可用向量候选按排名融合。精确别名不会因关键词频次过高而漏掉；
同名实体仍保留不同身份，名称匹配不证明两人相同，也不产生关系。

当前上游显式采纳入口只发布 `entails` / `contradicts`，可以先验证“某实体相关的记忆”。
遍历器虽支持五种类型，但蕴含不能用来回答因果问题，矛盾记录也不等于完成了全部冲突审计。
原因、结果、先后问答仍需要经过审核的对应关系及已知有效时间。返回覆盖状态保持
`incomplete`，不生成完整规则证明。下一步应做真实桌面审核→召回验收，并补充多关系样例。

## 召回路径与回答边界（2026-09-29）

召回侧现在把已有遍历结果通过可选 `evidence.relationRecall` 传给 Agent，包含：

- 实际查询的关系类型、方向和跳数上限；
- 每个起点到命题的一条最短发现路径，以及没有继续展开的深度边界；
- 已召回的直接原因分组、是否存在多个原因，以及限定搜索范围内的覆盖状态；
- `conflictAudit: not-supported`：当前桌面读取器不支持完整冲突审计，不能把它写成“没有矛盾”。

例如“暴雨→道路积水→公交停运”和“设备故障→公交停运”都存在时，回答可以列出来源中
记录的两个直接原因，并引用原始关系。不能凭两跳路径新增“暴雨直接导致公交停运”的关系，
也不能把多个原因自动当成互斥解释。逆向查找原因不改变关系本身的方向。

提示词构建前校验路径的精确端点、关系版本、方向、父节点深度、深度边界及原因分组；
伪造路径或隐去已返回的原因会被拒绝。说明与证据一起计算输出预算，预算不足时不拆散返回。
这是可选接口扩展，旧的直接事实证据包仍可使用。没有修改实体提取、自动建图或关系采纳政策。

`eval/l2-recall-explanation-regression.ts` 新增 15 项合成回归，覆盖多跳、分支原因、方向、
零跳/一跳、先后关系、无原因、循环、预算和说明篡改。验收基于已发布的测试图，
不要求上游自动提取因果关系，也不代表真实聊天数据或在线回答质量已通过验收。

## L2 起始命题选择（2026-09-29）

本节描述 `hybrid` 对照/兼容模式。桌面实验图默认的 `entity-vector` 模式先定位实体，
再对其关联 Claim 进行向量排序及身份、状态检查，不套用下述词项共现检查。

`recall/l2-seed-ranking.ts` 将关系召回的候选排序从宿主适配器中独立出来，使用
`l2-entity-target-rrf-v4` 策略：先使用与问题目标全文精确匹配的命题；不存在时使用
有权限的实体名称/别名精确入口；都不存在时再融合关键词（含实体名称/别名文本）与
可用向量候选。精确目标存在时，不用模糊邻近文本额外启动无关遍历。
“比赛取消”和“比赛取消通知”因此不会同时成为“为什么比赛取消”的起点。

名称比较只统一大小写、全半角、空白和句末标点，不删除否定词。同名实体、同文命题
以及引用同一 Fact 的不同 Claim 都保留精确身份；排序不会据此合并实体。候选受原有
maxSeeds 约束，截断时 trace 标记 `seed-top-k-truncated`，不宣称已覆盖全部候选。

有限问句解析新增礼貌前缀、“是什么原因”和句末“呢”的处理。没有精确入口时，改写
问法仍依赖实际向量模型的匹配能力；本轮没有硬编码同义事实或放宽向量准入阈值。
trace 同时记录入口选择策略、所用检索通道及向量缓存缺失/失败状态。

非精确入口在融合后、top-k 截断前增加目标词项共现检查。仅在已经通过权限和时间过滤的
命题正文、实体名称/别名中收集词项；问题目标中已在这些文本出现的词项，须同时出现在
单个候选中。关系/谓词的内部标识不能充当正文证据。例如只有“会议改期”和“比赛取消”
时，“会议取消”不再用这两条部分匹配记录同时启动遍历。高向量分数不能绕过此检查。
没有出现在当前候选语料的改写词不增加限制；原有精确正文和精确名称入口保持优先。

trace 新增 `seed-query-anchors`、`seed-anchor-rejected` 计数；没有合格起点时用
`seed-abstention:target-anchors-unresolved` 区分目标词项未能共同匹配，或
`seed-abstention:no-matching-candidate` 表示各入口均未命中。预算截断单独标记，
不能写成“库中没有答案”。空证据仍为 `incomplete`，仅表示本次搜索不足以支持回答。

这是一项保守的词项启发式，不是语义蕴含、实体消歧或否定判定器。词汇在其他记忆中
出现也可能增加限制，从而误过滤正确改写；全无词面重叠时仍依赖原有向量门槛。
本轮不降低默认 0.8 门槛、不提高遍历/输出预算、不改动关系采纳策略。

## 可选的语义补充入口（实验，默认关闭）

`V4L2MemoryOptions.semanticFallback` 允许宿主显式配置 `{ model, minCosine, minMargin }`。
此实验只在 `hybrid` 模式生效；关键词、事实向量和实体向量模式不会自动启用它。
`model` 必须等于当前嵌入模型的完整指纹；`minCosine` 必须低于正常门槛，`minMargin`
必须为正。配置不合法或模型指纹变化时不放宽检索，并在 trace 中记录原因。
桌面运行时目前不设置该选项，普通 L1 召回也不消费该选项。

只有常规起点选择为空且种子预算大于零时，才尝试补充：

1. 使用同一次问题向量计算，取得全部合格 Fact 中最接近的两个候选。第二名即使低于
   准入门槛也参与比较，避免阈值截断造成虚假的大分差。
2. 要求当前合格集合的向量缓存完整、至少有两个不同 Fact、首名分数达到下限且领先
   第二名达到指定差值。只一个向量、部分缓存、超时或模型不可用时不放宽。
3. 只把首名送回原来的目标词项、精确 Claim 身份和预算检查。首名被过滤后不提升第二名；
   同一 Fact 下的多个精确 Claim 仍分别受预算约束。通过之后才调用已有受限遍历器。

trace 使用 `semantic-fallback:*` 区分未需要、配置无效、缓存不完整、竞争不足、分数
不足、候选相近、目标不符及已准入，并记录实际首名分数/分差。分差不是正确率，
不生成关系，不改变人工采纳要求，也不能验证否定、状态变化或问题前提。

语义补充实验固定使用下限 0.6、分差 0.1。2026-09-29 的合成题集上有改写收益，
但反例暴露了“文件上传成功”误匹配“文件上传失败”等既有问题。随后增加的状态检查
见下文；分差本身仍不能验证问题前提，该选项保持默认关闭。

候选进入向量查询前检查有效时间、记录时间与审核时间。当前读取器仍拒绝不支持的
历史事务快照查询，不会静默改用当前视图；这不等于已经实现任意历史回溯。

`eval/l2-seed-regression.ts` 新增 15 项回归，验证目标与干扰项、否定、身份保留、
多通道去重、候选预算、口语问句、无答案、语义入口、历史视图拒绝及向量缺失回退。
语义入口使用明确的测试向量，只验证接线；实际模型改写召回率仍须单独测评。

## 有限的目标状态检查（2026-09-30）

新增 `recall/l2-target-state.ts`，在 L2 起点排序中区分少量中文表面表达：成功/失败
及无法/不能等不能完成的说法、恢复/故障/停用、取消/延期。非精确候选须能确认问题
中被识别的状态；状态不符或候选缺少状态确认时不进入遍历。高向量分数和精确实体别名
都不能绕过这项检查，单纯“故障”也不当作“停用”。

通用的成功/失败、无法/不能等词不再充当内容锚点。“资料无法上传”与“文件上传失败”
可以通过共同动作“上传”匹配；其他事实中的“无法”不会把这条正确候选排除。
只共享这类通用状态词的关键词命中不能确定目标事件，例如手机充电与自行车骑行。
已有合格向量候选仍可支持没有词面重叠的改写，但仍需满足状态和已知内容锚点。
取消、停运等事件动词保留原来的词面内容，不被统一删除。

对识别到的状态，如果还有未解析的否定、条件、计划、引述、多个冲突状态等表面信号，
非精确匹配保守返回证据不足。完整 Claim 文本精确匹配保留原文与身份，不做双重否定
改写。没有识别到状态的普通问题继续沿用已有策略。本模块既不是通用否定分析器，
也不是 NLI、身份消歧或因果证明器；同义状态只是候选兼容条件，不是事实蕴含。

trace 新增 `seed-state-rejected`、`seed-content-rejected`，空结果可标记
`target-state-unresolved` 或 `no-content-match`；复杂状态另有 `seed-target-state:ambiguous`。
每种计数独立统计，可能同时命中同一候选，不能相加当作拒绝总数。无法确认状态不能
解释为发现了矛盾关系。不会创建/采纳/修改关系，也不提高预算或降低桌面向量阈值。

## 显式实体约束与有效时间（2026-09-30）

`recall/l2-entity-target.ts` 从当前已授权、保留的 Claim 所引用的原生 Entity 中建立
名称/别名目录，约束以精确 Entity 引用的哈希表示。实体本身还需满足范围、分享权限、
敏感级别、审核、记录时间及未关闭要求。不会从原始未授权投影收集全局姓名，也不把
字符串相同视作身份相同。

该目录在有效时间过滤前建立，但仍服从 knownAt。比如林同学只有昨天的记录、周同学
有今天的记录，查询“今天林同学与 Acme 相关的记忆”仍保留林同学的实体约束；不能
因为林同学的记录被时间过滤掉，就改选同样涉及 Acme 的周同学记录。约束应用于全部
起点入口，包括精确文本、名称、向量及实验性补充入口；不提高任何预算。

名称匹配统一全半角与大小写，英文名称不作单词前缀匹配；被更长中文名称包含的短名
不独立绑定；单字姓名只在整个目标等于该名字时识别。多个名字要求单个起点满足所有
提及约束；非包含式的重叠名称保守拒绝。同名对应多实体时保留不同身份并标记歧义，
Agent 提示词会要求分开证据，必要时澄清，不自动选一个人。

trace 新增实体提及数、拒绝数、同名/重叠歧义及 `entity-target-unresolved`。只输出
诊断标记，不列出未命中的姓名目录。此约束只限定起点：之后沿已审核关系返回其他
人物的关联证据仍是允许的，不应把整个关联图裁成只包含一个人。

边界：没有原生实体引用的旧标量事实仍走原策略；不识别陌生姓名，不解析“他/她/我”，
不判断主客体角色。对“分别列出甲和乙的记忆”等并列问题，要求同一 Claim 包含所有
名字可能漏召回，尚未支持自动拆解成多个查询。有效时间范围查询不等于任意历史事务
快照，已有不支持的历史 knownAt 仍明确拒绝。真实人工验收见 `l2-real-memory-review.md`。

## Agent 召回结果状态说明

图证据进入 Agent 提示词前，会根据已校验的证据与 trace 生成 `retrievalAssessment`。
这是消费端的结果说明，不是新的事实、关系、置信度或持久化协议，也不修改检索排名。

| 状态 | 含义与回答边界 |
|---|---|
| `direct-evidence` | 返回直接陈述，只能支持原文内容，不能自行建立关系。 |
| `no-direct-evidence` | 本次没有返回合格直接证据，不代表用户没有该经历。 |
| `no-target-evidence` | 关系问题没有返回合格目标证据，不能据此否认事件或原因存在。 |
| `target-only` | 返回了目标事件，但未返回所问关系；可以引用事件，不能补写原因、结果或顺序。 |
| `relation-evidence` | 返回关系证据；仍需按起点分别判断，并保留检索范围限制。 |

每个已返回的起点带有引用编号、直接相连且符合查询方向/类型的关系引用，以及
`relations-returned`、`no-matching-relations-returned` 或 `not-expanded` 状态。
某一起点查到原因，不表示其他起点也已得到原因。零跳时明确标为未扩展；存在边界节点
时保留跳数限制。无匹配仅描述本次返回的证据，不宣称整个图中没有关系。

覆盖不完整、起点截断、语义缓存不完整和同名歧义分别保留。筛选原因仅允许固定标签，
不从记忆正文生成指令。原始证据、路径与 trace 仍随提示词返回，整个 JSON 保持转义。
桌面宿主的节点/时间/输出预算错误仍作为错误返回，不转换为成功的空答案。

`l2AnswerStatus` 使用合成数据调用真实 L1/L2 适配器和提示词构建器；它检验证据交接，
不代表远程聊天模型一定遵循说明，也不评估真实用户记忆或最终回答质量。

## L1 结构化问题入口

默认启用 `direct-structured-slots-v1`：识别有限的本人饮品偏好问题，例如“偏爱的饮品
是哪种”“我喜欢喝什么”，从已通过权限、来源、版本和时间过滤的输入中按
`subjectId === scope.ownerId`、`predicate === 'preference.drink'` 精确取候选。
它将已有字段用于查找，不解析或改写记忆，不从值中猜测类别，也不生成答案。

结构化候选参与现有 RRF。该字段在合格语料中存在时，对融合结果施加相同主体/字段
约束后再执行 top-k 和输出预算，避免其他人的饮品或本人的食物偏好替代目标。
若合格语料中不存在这一精确字段，则不施加新约束，继续原有关键词/向量路径。
第三人称、否定问句、复杂附加条件不进入本轮有限语法；一般实体消歧仍不是它的能力。

`structuredRecall: false` 是可信宿主的对照选项，桌面默认不设置它，因此普通问题
经 L2 宿主分流到 L1 后自动使用新入口。此设置不改变 L2 关系问题的起点排序，也不
改变全局向量门槛。否定证据可被召回但保留否定，不能据此断言正向偏好。

原始 12 题在默认路径全部通过，纯 BM25 对照保持 11/12；真实本地模型和额外的
22 项结构化检查已复跑。公开 benchmark、真实用户样本和最终聊天回答质量尚未由此验证。
